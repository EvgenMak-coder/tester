## Теория

У каждого модуля в поле `theory` записан план теории на три уровня: о чём должен рассказывать раздел, чтобы читатель справился с вопросами этого уровня.

Тексты разделов лежат в каталоге `theory/`, по файлу на уровень: `theory/01-shell.basic.md`, `theory/01-shell.intermediate.md`, `theory/01-shell.advanced.md`. Имя файла — имя файла модуля, точка, уровень. Пока файла нет, модуль показывает план с пометкой «готовится»; когда он появляется — кнопку «Читать».

Написано: модули 1–6 (от «Оболочки и командной строки» до «Пользователей и групп»), все три уровня. Остальные 13 модулей — только планы.

Правила для текстов:

1. **Раздел идёт по своему плану** и закрывает вопросы своего уровня: прочитав его, на них можно ответить.
2. **Уровни не повторяют друг друга.** Средний опирается на базовый, продвинутый — на оба.
3. **Сначала зачем, потом как.** Каждая тема начинается с задачи, которую она решает, и сопровождается примером команды.
4. **В конце — раздел «Коротко»** со списком того, что нужно запомнить.
5. **Разметка — только поддерживаемая приложением** (см. `docs/FORMAT.md`): заголовки, абзацы, списки без вложенности, блоки кода, врезки, полужирный и код в строке. Тесты это проверяют.
6. **Примеры команд по возможности проверяются запуском.**

## Как устроены файлы

`course.json` — шапка курса: `format`, `version` и блок `course`. Каждый файл модуля — одна тема в формате из `docs/FORMAT.md`:

```json
{
  "id": "shell",
  "title": "Оболочка и командная строка",
  "icon": "terminal",
  "description": "Одна строка о содержании модуля",
  "questions": []
}
```

Приложение собирает курс из шапки и всех файлов модулей и проверяет его целиком, как обычный файл курса.

## Правила для вопросов курса

Сверх общих правил из `docs/FORMAT.md`:

1. **Идентификаторы.** Префикс модуля и номер: `sh-001`, `file-001`, `perm-001`, `net-001`. Номера не переиспользуются, новые вопросы получают следующие номера независимо от уровня.
2. **Уровни.** Базовый — что делает команда и какой ключ нужен. Средний — как это устроено и что выбрать в типовой ситуации. Продвинутый — диагностика по выводу, пограничные случаи, внутреннее устройство.
3. **У каждого неверного варианта есть разбор** в поле `notes`: что это на самом деле или когда было бы верно. Тесты проверяют, что разбор есть везде.
4. **Верный ответ не выделяется.** Он не должен быть заметно длиннее или подробнее остальных; тесты проверяют это автоматически. Позиция верного варианта чередуется.
5. **Проверка на деле.** Вопросы вида «что выведет команда» по возможности проверяются запуском этой команды; расхождение исправляется до публикации.
6. **Темы не дублируются между модулями.** Например, tar относится к модулю 15, а не к «Файлам», пользователи и sudoers — к модулю 6, а не к «Правам».
