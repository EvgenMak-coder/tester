# Unit-файл

Всё, чем управляет systemd, описано в небольших текстовых файлах — **юнитах**. Юнит службы называется `имя.service`. Вот минимальный пример для собственного приложения:

```
[Unit]
Description=Сервер приложения
After=network.target

[Service]
ExecStart=/usr/bin/python3 /opt/app/server.py
User=app
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

В файле три раздела.

- **[Unit]** — описание и связи с другими юнитами. `After` задаёт порядок запуска.
- **[Service]** — как запускать. `ExecStart` — команда запуска с полным путём, `User` — от чьего имени.
- **[Install]** — что происходит при `enable`. `WantedBy=multi-user.target` означает «запускать при обычной загрузке».

# Где лежат юниты

Юниты хранятся в трёх каталогах, и важен приоритет.

- `/usr/lib/systemd/system` — файлы из пакетов. Их не правят: обновление пакета затрёт изменения.
- `/etc/systemd/system` — файлы администратора. Сюда кладут собственные юниты. Этот каталог важнее предыдущего.
- `/run/systemd/system` — временные, до перезагрузки.

Какой файл на самом деле используется, показывает `systemctl cat nginx`.

# После правки — daemon-reload

systemd читает юниты один раз и держит их в памяти. Изменив файл на диске, нужно сказать ему об этом:

```
sudo systemctl daemon-reload
sudo systemctl restart app
```

Если забыть, systemd продолжит использовать старую версию и предупредит:

```
Warning: The unit file, source configuration file or drop-ins of app.service changed on disk.
```

`daemon-reload` перечитывает описания юнитов и ничего не перезапускает. Чтобы изменения подействовали на работающую службу, её нужно перезапустить отдельно.

# Изменить службу из пакета

Править файл в `/usr/lib/systemd/system` нельзя, копировать его целиком в `/etc` — неудобно. Для точечных изменений есть дополнения:

```
sudo systemctl edit nginx
```

Команда открывает редактор и сохраняет написанное в файл `/etc/systemd/system/nginx.service.d/override.conf`. В нём указывают только то, что меняется:

```
[Service]
Restart=always
```

Всё остальное берётся из исходного юнита, а при обновлении пакета дополнение остаётся на месте. После сохранения `systemctl edit` сам выполняет `daemon-reload`; перезапустить службу нужно вручную.

# reload и restart

```
sudo systemctl reload nginx
sudo systemctl restart nginx
```

`restart` останавливает службу и запускает заново. Все соединения обрываются.

`reload` просит службу перечитать свои настройки, не останавливаясь. Соединения сохраняются. Умеют это не все службы: только те, у которых в юните задана директива `ExecReload`. Для остальных есть `reload-or-restart`.

Не путайте: `reload` относится к настройкам самой программы, например `/etc/nginx/nginx.conf`, а `daemon-reload` — к unit-файлам.

# Включить и запустить разом

```
sudo systemctl enable --now nginx
```

Ключ `--now` объединяет `enable` и `start`: служба и запустится сейчас, и будет подниматься при загрузке. У `disable --now` обратное действие.

# Автоматический перезапуск

Упавшую службу systemd может поднять сам:

```
[Service]
Restart=on-failure
RestartSec=5
```

- `Restart=on-failure` — перезапускать, если служба завершилась с ошибкой или была убита сигналом;
- `Restart=always` — перезапускать при любом завершении;
- `RestartSec=5` — ждать пять секунд перед новой попыткой.

Службы, завершившиеся с ошибкой, собраны в одном списке:

```
systemctl --failed
```

С этой команды стоит начинать осмотр сервера после перезагрузки.

# Цели

**Цель** (target) — именованное состояние системы: набор юнитов, которые должны быть запущены.

- `multi-user.target` — обычная работа сервера: сеть, службы, вход с консоли, без графики;
- `graphical.target` — то же плюс графический вход;
- `rescue.target` — режим восстановления с минимумом служб;
- `poweroff.target` и `reboot.target` — выключение и перезагрузка.

```
systemctl get-default
sudo systemctl set-default multi-user.target
```

Первая команда показывает, в какую цель система загружается, вторая меняет её. Цели заменили уровни запуска старой системы инициализации.

# mask сильнее, чем disable

`disable` только убирает автозапуск. Отключённую службу по-прежнему можно запустить вручную, и её может запустить другая служба, которой она нужна.

```
sudo systemctl mask nginx
sudo systemctl unmask nginx
```

`mask` делает запуск невозможным вообще: ни вручную, ни по зависимости. Технически он ставит на место юнита ссылку на `/dev/null`. Так поступают со службами, которые не должны запуститься ни при каких обстоятельствах.

# Коротко

- Юнит службы: разделы [Unit], [Service], [Install]; команда запуска — `ExecStart`.
- Свои юниты кладут в `/etc/systemd/system`.
- После правки unit-файла — `systemctl daemon-reload`, затем перезапуск службы.
- `systemctl edit имя` создаёт дополнение, которое переживает обновление пакета.
- `reload` перечитывает настройки без остановки, `restart` перезапускает.
- `enable --now` включает автозапуск и запускает сразу.
- `Restart=on-failure` поднимает упавшую службу; `systemctl --failed` показывает упавшие.
- `multi-user.target` — обычный режим сервера.
- `mask` запрещает запуск совсем.
