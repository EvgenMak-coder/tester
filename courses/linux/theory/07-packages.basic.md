# Откуда берутся программы

В Linux программы обычно не скачивают с сайтов разработчиков. Их устанавливает **менеджер пакетов** — программа, которая сама находит нужное, скачивает, раскладывает файлы по местам и следит за обновлениями.

Три понятия, на которых всё держится:

- **Пакет** — архив с программой: её файлы, описание, номер версии и список того, что нужно ей для работы.
- **Репозиторий** — хранилище пакетов на сервере. Его ведёт дистрибутив, реже — сторонний разработчик. Пакеты в нём подписаны, поэтому подмену менеджер заметит.
- **Зависимости** — другие пакеты, без которых программа не запустится. Чаще всего это общие библиотеки.

Главное удобство менеджера пакетов — зависимости он находит и ставит сам.

# Два семейства

Дистрибутивы делятся на семейства по формату пакетов.

- **Debian, Ubuntu, Mint** — пакеты `.deb`, менеджер `apt`.
- **Fedora, RHEL, AlmaLinux, Rocky** — пакеты `.rpm`, менеджер `dnf`.

Есть и другие: `pacman` в Arch, `zypper` в openSUSE. Команды называются по-разному, но делают одно и то же. Дальше примеры даны для `apt`, а соответствия для `dnf` — в конце раздела.

# Установить и удалить

```
sudo apt install htop
sudo apt remove htop
```

`install` скачивает пакет вместе с зависимостями и устанавливает. Перед началом `apt` покажет, что именно будет установлено и сколько места займёт, и спросит подтверждение.

`remove` удаляет программу. Удалять её файлы вручную, командой `rm`, нельзя: менеджер будет считать пакет установленным, и следующие обновления пойдут вкривь.

# Почему нужен sudo

Пакеты кладут файлы в системные каталоги — `/usr`, `/etc` и другие, куда обычный пользователь писать не может. Поэтому всё, что меняет систему, выполняют через `sudo`: установку, удаление, обновление.

Искать пакеты и читать их описания можно без `sudo`.

# update и upgrade

Эти две команды путают чаще всего, а делают они разное.

```
sudo apt update
sudo apt upgrade
```

`apt update` **ничего не устанавливает**. Он скачивает из репозиториев свежие списки: какие пакеты и каких версий там сейчас есть.

`apt upgrade` сравнивает эти списки с установленным и обновляет всё, для чего вышла новая версия.

Поэтому их запускают парой и именно в таком порядке. Без `update` система не узнает, что появились обновления.

> Перед установкой нового пакета тоже полезно выполнить `apt update`. Со старыми списками `apt` может попытаться скачать версию, которой в репозитории уже нет.

# Найти пакет

Название пакета не всегда совпадает с названием программы. Найти его помогает поиск по словам из описания:

```
apt search "disk usage"
apt show ncdu
```

`apt search` ищет в названиях и описаниях. `apt show` выводит подробности об одном пакете: версию, размер, зависимости, описание.

Проверить, установлен ли пакет, можно так:

```
apt list --installed | grep nginx
```

# То же самое в Fedora и RHEL

- `sudo dnf install htop` — установить;
- `sudo dnf remove htop` — удалить;
- `sudo dnf upgrade` — обновить всё;
- `dnf search слово` — найти;
- `dnf info пакет` — подробности.

Отдельной команды вроде `apt update` у `dnf` нет: списки он обновляет сам, когда они устаревают.

# Коротко

- Программы ставят менеджером пакетов из репозиториев, а не с сайтов.
- Зависимости менеджер находит и ставит сам.
- Debian и Ubuntu — `.deb` и `apt`; Fedora и RHEL — `.rpm` и `dnf`.
- `apt install пакет`, `apt remove пакет` — через `sudo`.
- `apt update` обновляет списки, `apt upgrade` — сами программы.
- `apt search` ищет по описанию, `apt show` показывает подробности.
