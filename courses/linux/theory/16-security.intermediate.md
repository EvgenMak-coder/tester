# Политика по умолчанию

У межсетевого экрана два вида настроек: правила для конкретных соединений и **политика по умолчанию** — что делать с соединением, которому не подошло ни одно правило.

```
sudo ufw default deny incoming
sudo ufw default allow outgoing
```

Это обычная схема для сервера. Всё входящее, что не разрешено явно, отбрасывается. Всё исходящее разрешено: сервер может скачивать обновления и обращаться к другим службам.

Дальше открывают только нужное:

```
sudo ufw allow ssh
sudo ufw allow 443/tcp
sudo ufw allow from 10.0.0.0/8 to any port 5432
sudo ufw status numbered
sudo ufw delete 3
```

Третья строка разрешает доступ к порту базы данных только из внутренней сети. `status numbered` нумерует правила, чтобы их можно было удалять по номеру.

Порядок действий на удалённом сервере всегда один: сначала `ufw allow ssh`, потом `ufw enable`. Включённый экран с политикой `deny` и без правила для SSH не пустит новое подключение, и чинить придётся через консоль хостинга.

# firewalld

В Fedora и RHEL экраном управляет `firewalld`. У него две особенности.

**Зоны.** Правила сгруппированы по уровню доверия к сети: `public`, `internal`, `trusted`. Каждый интерфейс относится к одной зоне.

**Два набора правил.** Действующий, который работает сейчас, и постоянный, который загружается при старте.

```
sudo firewall-cmd --add-service=https
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload
sudo firewall-cmd --list-all
```

Команда без `--permanent` меняет только действующий набор: правило работает сразу, но исчезнет после перезагрузки. С `--permanent` меняется только постоянный набор: правило сохранится, но начнёт действовать после `--reload`.

Это удобно для проб: неудачное правило само пропадёт при перезагрузке. Но из-за этого же правила, добавленные «на минуту», часто забывают сохранить.

# SELinux: режимы

```
getenforce
sudo setenforce 0
```

У SELinux три режима:

- **Enforcing** — политика действует: запрещённое блокируется и записывается в журнал;
- **Permissive** — ничего не блокируется, но нарушения записываются;
- **Disabled** — выключен.

`getenforce` показывает текущий режим. `setenforce 0` переключает в Permissive, `setenforce 1` — обратно, оба действуют до перезагрузки. Постоянный режим задаётся в `/etc/selinux/config`.

Режим Permissive нужен для диагностики. Если программа в нём заработала, значит мешала политика SELinux, а журнал покажет, какое именно действие было бы запрещено. После этого политику исправляют и возвращают Enforcing, а не оставляют защиту выключенной.

# AppArmor: профили

В Ubuntu и Debian ту же задачу решает AppArmor. Он проще устроен: для каждой программы есть **профиль** — текстовый файл в `/etc/apparmor.d/` с перечнем того, что ей разрешено.

```
sudo aa-status
```

Команда показывает загруженные профили и режим каждого:

- **enforce** — нарушения блокируются;
- **complain** — только записываются, аналог Permissive.

Отказы AppArmor попадают в журнал ядра со словом `DENIED`: `sudo dmesg | grep DENIED`.

# Автоматические обновления

Исправления безопасности нужно ставить быстро, а помнить о них ежедневно невозможно. В Debian и Ubuntu это делает пакет `unattended-upgrades`:

```
sudo apt install unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades
```

По умолчанию он сам устанавливает только обновления безопасности. Остальные обновления ждут администратора: они реже срочны и чаще что-то меняют в поведении.

В Fedora и RHEL ту же задачу решает `dnf-automatic`.

Часть обновлений — ядро, системные библиотеки — вступает в силу только после перезагрузки. О необходимости перезагрузки говорит файл `/var/run/reboot-required`.

# Шифрование файла: gpg

Чтобы передать файл по ненадёжному каналу или положить в облако, его шифруют:

```
gpg -c secret.txt
gpg -d secret.txt.gpg > secret.txt
```

`gpg -c` спрашивает пароль и создаёт зашифрованный файл `secret.txt.gpg`. Это симметричное шифрование: тот же пароль нужен для расшифровки. Исходный файл остаётся на месте, и удалять его нужно отдельно.

`gpg -d` расшифровывает и выводит содержимое.

# Контрольные суммы

Рядом с образами систем и архивами программ публикуют их контрольные суммы. Сумма — короткая строка, вычисленная из содержимого файла. Изменение одного бита меняет её до неузнаваемости.

```
sha256sum ubuntu.iso
sha256sum -c SHA256SUMS
```

Первая команда вычисляет сумму файла, и её сравнивают с опубликованной. Вторая сама сверяет файлы по списку.

Совпадение означает, что файл не повредился при скачивании и не был подменён. Второе верно при одном условии: сама сумма получена из надёжного источника. Если взломан сайт, подменят и файл, и сумму. От этого защищает подпись, о ней — на продвинутом уровне.

# Зашифрованный раздел: LUKS

Шифрование дисков в Linux устроено через LUKS. Зашифрованный раздел нельзя смонтировать напрямую: сначала его открывают паролем.

```
sudo cryptsetup open /dev/sdb1 secret
sudo mount /dev/mapper/secret /mnt/secret
```

После ввода пароля появляется новое устройство — `/dev/mapper/secret`. Оно расшифровывает данные на лету, и именно его монтируют как обычный раздел. На самом диске данные остаются зашифрованными.

Закрывают в обратном порядке:

```
sudo umount /mnt/secret
sudo cryptsetup close secret
```

Создаёт зашифрованный раздел команда `cryptsetup luksFormat`. Она уничтожает всё, что было на разделе.

# Коротко

- Политика по умолчанию: `deny incoming`, `allow outgoing`, затем разрешения для нужных портов.
- В `firewalld` правило без `--permanent` исчезнет после перезагрузки; с ним — нужен `--reload`.
- SELinux: Enforcing блокирует, Permissive только записывает; `getenforce` показывает режим.
- AppArmor: профили в режимах enforce и complain; `aa-status` показывает их.
- `unattended-upgrades` сам ставит обновления безопасности.
- `gpg -c файл` шифрует паролем.
- `sha256sum` проверяет, что файл не повреждён и не подменён.
- `cryptsetup open` создаёт расшифрованное устройство в `/dev/mapper`.
