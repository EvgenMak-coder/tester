# Отбор записей в journalctl

Журнал занятого сервера — это миллионы строк. Сила `journalctl` в том, что он умеет отбирать нужное по нескольким признакам сразу.

**По службе:**

```
journalctl -u nginx
```

**По времени:**

```
journalctl --since "1 hour ago"
journalctl --since "2026-10-07 09:00" --until "2026-10-07 10:00"
journalctl --since yesterday
```

Понимаются и точные даты, и относительные выражения.

**По загрузке:**

```
journalctl -b
journalctl -b -1
journalctl --list-boots
```

`-b` без числа — текущая загрузка, `-b -1` — предыдущая, `-b -2` — позапрошлая. Если сервер неожиданно перезагрузился, причину ищут в конце журнала предыдущей загрузки: `journalctl -b -1 -e`. Ключ `-e` сразу переносит в конец.

**Только сообщения ядра:**

```
journalctl -k
```

Это то же, что выводит `dmesg`, но с возможностью заглянуть в прошлые загрузки.

Условия сочетаются: `journalctl -u nginx -p err --since today` покажет сегодняшние ошибки одной службы.

# Уровни важности

Каждому сообщению присвоен уровень важности. Их восемь, от самого серьёзного:

- `emerg` (0) — система неработоспособна;
- `alert` (1) — нужно действовать немедленно;
- `crit` (2) — критическая ошибка;
- `err` (3) — ошибка;
- `warning` (4) — предупреждение;
- `notice` (5) — обычное, но заметное событие;
- `info` (6) — информация;
- `debug` (7) — отладка.

Ключ `-p` задаёт порог:

```
journalctl -p err
journalctl -p warning -b
```

Первая команда покажет сообщения уровня `err` **и все более серьёзные**. Предупреждения и обычные сообщения в вывод не попадут. Это быстрый способ отсеять шум и увидеть только проблемы.

# Сколько места занимает журнал

```
journalctl --disk-usage
```

Журнал systemd хранится в двоичном виде в `/var/log/journal` и на загруженном сервере вырастает до нескольких гигабайт.

# rsyslog: журналы в файлах

Привычные текстовые файлы в `/var/log` ведёт служба **rsyslog**. Она получает сообщения и раскладывает их по правилам из `/etc/rsyslog.conf` и каталога `/etc/rsyslog.d/`.

Правило состоит из отбора и действия:

```
auth,authpriv.*    /var/log/auth.log
kern.*             /var/log/kern.log
*.emerg            :omusrmsg:*
```

Отбор записывается как `источник.уровень`.

- **Источник** — откуда сообщение: `auth` — вход в систему, `kern` — ядро, `mail` — почта, `cron` — планировщик. Несколько источников перечисляют через запятую.
- **Уровень** — те же восемь уровней важности. Звёздочка означает «любой».

Действие — обычно путь к файлу. Первая строка читается так: сообщения источников `auth` и `authpriv` любого уровня записывать в `/var/log/auth.log`.

# Настройка logrotate

Правила ротации лежат в `/etc/logrotate.conf` и в каталоге `/etc/logrotate.d/`, по файлу на программу. Собственному приложению, которое пишет журнал в файл, нужно своё правило:

```
/var/log/app/*.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

- `daily` — как часто: ещё бывают `weekly` и `monthly`;
- `rotate 7` — сколько старых файлов хранить. Более давние удаляются;
- `compress` — сжимать старые файлы;
- `missingok` — не считать ошибкой отсутствие файла;
- `notifempty` — не трогать пустой журнал.

Вместе `daily` и `rotate 7` дают неделю истории. Проверить правило, ничего не меняя, позволяет `sudo logrotate -d /etc/logrotate.d/app`.

# Запись из скриптов: logger

Собственные скрипты тоже должны оставлять следы. Команда `logger` записывает строку в системный журнал:

```
logger "резервная копия готова"
logger -t backup -p user.err "не удалось подключить диск"
```

Ключ `-t` задаёт метку, по которой записи потом находят: `journalctl -t backup`. Ключ `-p` задаёт источник и уровень. Сообщение получает отметку времени и попадает туда же, куда и сообщения служб.

# Наблюдение в реальном времени

Журналы рассказывают о прошлом. Чтобы видеть, что происходит сейчас, есть три простых инструмента.

**watch** повторяет любую команду с заданным интервалом и перерисовывает экран:

```
watch -n 5 df -h
```

Здесь `df -h` выполняется каждые пять секунд. Без `-n` интервал равен двум секундам, ключ `-d` подсвечивает изменения.

**vmstat** печатает строку общей статистики раз в заданный интервал: процессы, память, подкачка, диск, процессор.

```
vmstat 5
```

**iostat** показывает нагрузку на каждый диск:

```
iostat -x 1
```

Ключ `-x` включает расширенную статистику: число операций, время ожидания, занятость. Число в конце — интервал в секундах. Команда входит в пакет `sysstat`.

# Коротко

- `journalctl` отбирает по службе (`-u`), времени (`--since`), загрузке (`-b -1`), ядру (`-k`).
- Уровней важности восемь, от `emerg` до `debug`; `-p err` показывает `err` и всё, что серьёзнее.
- `journalctl --disk-usage` — размер журнала.
- Правило rsyslog: `источник.уровень` и файл назначения.
- logrotate: `daily` — период, `rotate 7` — сколько файлов хранить.
- `logger` пишет в журнал из скриптов.
- `watch -n 5 команда` повторяет команду, `vmstat 5` и `iostat -x 1` показывают нагрузку.
