# Что такое SSH

SSH — это способ работать в командной строке другого компьютера по сети. Вы набираете команды у себя, а выполняются они на сервере, который может стоять в соседней комнате или на другом континенте. Почти всё администрирование серверов происходит именно так.

Всё, что передаётся по SSH, зашифровано: команды, их вывод и пароль. Посторонний в той же сети увидит только факт соединения.

Участвуют две программы: **клиент** `ssh` на вашем компьютере и **сервер** `sshd` на удалённом. Сервер ждёт подключений на порту 22.

# Подключиться

```
ssh anna@192.168.1.10
ssh anna@server.example.com
```

Запись состоит из двух частей, разделённых знаком `@`:

- `anna` — имя учётной записи **на удалённом компьютере**. Оно может не совпадать с вашим локальным именем;
- после `@` — адрес или имя сервера.

Если имя не указать, `ssh` подставит ваше локальное.

Дальше сервер спросит пароль этой учётной записи. При вводе он не отображается. После входа приглашение изменится: в нём будет имя сервера, и все команды теперь выполняются там.

# Первое подключение

Подключаясь к серверу впервые, вы увидите вопрос:

```
The authenticity of host 'server (203.0.113.10)' can't be established.
ED25519 key fingerprint is SHA256:9fT2mQxW4uLr0aVdK7sYpHc1ZbNe6oJgI3wXyB8tU5E.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Это не ошибка. У каждого сервера есть собственный ключ, и клиент видит его впервые. После ответа `yes` ключ запоминается, и вопрос больше не появится. Если ключ сервера когда-нибудь изменится, `ssh` предупредит: так он защищает от подмены сервера.

# Выйти

```
exit
```

Команда завершает сеанс на сервере и возвращает вас в свой терминал. То же делает сочетание Ctrl+D.

Понять, где вы сейчас, проще всего по приглашению: в нём написано имя компьютера. Привычка смотреть на него перед опасной командой спасает от выполнения её не на той машине.

# Другой порт

Сервер SSH не обязательно слушает порт 22. Другой порт указывают ключом `-p`:

```
ssh -p 2222 anna@server
```

Запись через двоеточие, как в адресах сайтов, здесь не работает: `ssh anna@server:2222` будет искать компьютер с таким именем.

# Выполнить одну команду

Открывать сеанс не обязательно. Команду можно дописать в конец:

```
ssh anna@server uptime
ssh anna@server "df -h /var"
```

`ssh` подключится, выполнит команду на сервере, покажет её вывод у вас и закроет соединение. Команду с пробелами и особыми знаками берут в кавычки, чтобы её не обработала ваша собственная оболочка.

# Копировать файлы: scp

`scp` копирует файлы по тому же защищённому каналу. Порядок как у `cp`: сначала откуда, потом куда. Удалённую сторону записывают как `пользователь@сервер:путь`.

```
scp report.pdf anna@server:/home/anna/
scp anna@server:/var/log/app.log .
scp -r site/ anna@server:/var/www/
```

Первая команда отправляет файл на сервер, вторая — забирает с сервера в текущий каталог (точка в конце). Для каталогов нужен ключ `-r`.

Другой порт у `scp` задаётся заглавной `-P`, в отличие от `ssh`.

# Ключи вместо пароля

Вводить пароль при каждом подключении неудобно, а пароль на сервере, доступном из интернета, ещё и небезопасен: его непрерывно подбирают автоматические программы. Поэтому вместо пароля используют **пару ключей**.

Пара состоит из двух файлов, созданных вместе:

- **закрытый ключ** остаётся у вас и никому не передаётся. Это ваша личность;
- **открытый ключ** можно раздавать свободно. Его размещают на серверах, куда вы хотите входить.

Сервер, у которого есть ваш открытый ключ, может проверить, что у подключающегося есть закрытый, не видя его самого. По открытому ключу закрытый восстановить нельзя.

Создаёт пару команда `ssh-keygen`:

```
ssh-keygen -t ed25519
```

Ключи и остальные личные настройки `ssh` хранит в каталоге `~/.ssh`: закрытый ключ в файле `id_ed25519`, открытый — в `id_ed25519.pub`. Как разместить открытый ключ на сервере, рассказано на среднем уровне.

# Коротко

- SSH — зашифрованный доступ к командной строке удалённого компьютера, порт 22.
- `ssh пользователь@сервер`; имя — учётная запись на сервере.
- Вопрос о ключе при первом подключении — норма; ответ `yes`.
- `exit` завершает сеанс.
- Другой порт: `ssh -p 2222`.
- `ssh сервер команда` выполняет одну команду и отключается.
- `scp файл пользователь@сервер:путь` копирует файлы; `-r` для каталогов.
- Пара ключей: закрытый хранят у себя, открытый размещают на серверах; создаёт её `ssh-keygen`.
