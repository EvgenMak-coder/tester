# Жадность

Знак `*` в регулярных выражениях жадный: он захватывает столько символов, сколько возможно. Шаблон `<.*>` совпадёт не с первым тегом, а со всем, что лежит от первой угловой скобки до последней:

```
echo 'a<b>c<d>e' | sed 's/<.*>//'
```

Результат — `ae`: пропало всё от первой `<` до последней `>`.

Чтобы остановиться на ближайшей закрывающей скобке, вместо «любой символ» пишут «любой символ, кроме скобки»:

```
echo 'a<b>c<d>e' | sed 's/<[^>]*>//g'
```

Теперь результат — `ace`: каждый тег удалён отдельно. Приём с `[^…]*` — основной способ обуздать жадность в `grep` и `sed`.

# Базовые и расширенные выражения

У `grep` и `sed` два диалекта регулярных выражений. В базовом, который включён по умолчанию, знаки `|`, `+`, `?`, круглые и фигурные скобки — обычные символы. Поэтому такая команда ничего не найдёт:

```
grep 'error|warn' app.log
```

Она ищет буквальную строку из десяти символов с вертикальной чертой посередине. Расширенный диалект включает ключ `-E`:

```
grep -E 'error|warn' app.log
grep -E '[0-9]+ ms' latency.log
grep -E '^(GET|POST) /api' access.log
```

В нём `|` означает «или», `+` — «один раз или больше», `?` — «ноль или один раз», скобки группируют. У `sed` тот же ключ: `sed -E`.

Ещё один ключ меняет не поиск, а вывод:

```
grep -oE '[0-9]+ ms' latency.log
```

С `-o` печатается не вся строка, а только совпавший фрагмент, каждый на отдельной строке. Так из журнала вытаскивают значения для дальнейших подсчётов.

# Правка на месте: sed -i

Обычно `sed` печатает результат на экран. Ключ `-i` заставляет его изменить сам файл:

```
sed -i 's/debug/info/g' app.conf
sed -i.bak 's/debug/info/g' app.conf
```

Вторая форма безопаснее: суффикс сразу после ключа велит сохранить прежнюю версию под именем `app.conf.bak`.

Отмены у `sed -i` нет. Поэтому сначала команду запускают без `-i`, смотрят на результат и только потом добавляют ключ.

# awk: условия и подсчёты

`awk` — небольшой язык для обработки таблиц. Программа на нём состоит из пар «условие — действие»:

```
awk -F: '$3 >= 1000 {print $1}' /etc/passwd
```

Для каждой строки `awk` проверяет условие перед фигурными скобками и, если оно истинно, выполняет действие. Здесь печатается имя учётной записи, у которой третье поле (UID) не меньше 1000, — получается список обычных пользователей.

Встроенные переменные: `NR` — номер текущей строки, `NF` — число полей в ней.

```
awk 'NR == 1' report.txt
awk 'NF > 0' report.txt
```

Блок `END` выполняется один раз, после последней строки. В нём выводят итог:

```
awk '{sum += $5} END {print sum}' sizes.txt
awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' access.log
```

Первая команда складывает пятое поле всех строк. Вторая считает, сколько раз встретилось каждое значение первого поля: `count` — это таблица, где ключом служит адрес.

# Разбор журнала конвейером

Самый узнаваемый конвейер администратора — «кто чаще всего обращался к серверу»:

```
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
```

По шагам:

1. `awk` оставляет от каждой строки первое поле — адрес клиента.
2. `sort` собирает одинаковые адреса рядом.
3. `uniq -c` схлопывает повторы и ставит перед адресом их число.
4. `sort -rn` сортирует по этому числу, от большего к меньшему.
5. `head -5` берёт пять верхних строк.

Меняя первое звено, тем же способом получают другие ответы: `$9` в журнале веб-сервера — код ответа, `$7` — запрошенный адрес.

# Сортировка чисел

По умолчанию `sort` сравнивает строки посимвольно, как текст. Поэтому `10` окажется раньше `9`: символ `1` меньше символа `9`.

- `sort -n` сравнивает как числа;
- `sort -h` понимает размеры с единицами: `2K`, `15M`, `1G`;
- `sort -k 2` сортирует по второму полю, а не по началу строки.

```
du -sh /var/* | sort -h
```

# cut и выровненный вывод

Вывод многих команд выровнен разным числом пробелов. `cut` на нём ошибается:

```
ps aux | cut -d' ' -f2
ps aux | awk '{print $2}'
```

Для `cut` каждый пробел — отдельный разделитель, и между двумя пробелами подряд он видит пустое поле. `awk` считает любую последовательность пробелов одним разделителем. Поэтому первая команда выдаёт в основном пустые строки, а вторая — номера процессов.

# xargs и имена с пробелами

`xargs` читает строки со своего ввода и превращает их в аргументы команды:

```
grep -rl "TODO" src/ | xargs wc -l
```

По умолчанию он делит ввод по пробелам и переводам строк. Имя `old report.log` превратится в два аргумента, и команда получит не тот файл. С `rm` это опасно.

Надёжный способ — разделять имена нулевым байтом, который в имени файла встретиться не может:

```
find . -name '*.log' -print0 | xargs -0 rm
```

Ключ `-print0` у `find` и ключ `-0` у `xargs` всегда используют парой.

# Окончания строк из Windows

В Linux строка заканчивается одним символом перевода строки. В Windows — двумя: возвратом каретки и переводом строки. Лишний символ невидим, но ломает скрипты:

```
bash: ./deploy.sh: /bin/bash^M: bad interpreter: No such file or directory
```

`^M` — это и есть возврат каретки. Ядро ищет интерпретатор с именем, в конце которого стоит этот символ, и не находит.

Проверить файл можно двумя способами:

```
file deploy.sh
cat -A deploy.sh
```

`file` сообщит `with CRLF line terminators`, а `cat -A` покажет `^M$` в конце каждой строки. Исправляют файл так:

```
sed -i 's/\r$//' deploy.sh
```

То же делает программа `dos2unix`, если она установлена.

# Кодировки

Вторая частая неприятность с чужими файлами — кодировка. Узнать её и преобразовать помогают две команды:

```
file -i report.txt
iconv -f cp1251 -t utf-8 report.txt > report-utf8.txt
```

`file -i` покажет, например, `charset=iso-8859-1` или `charset=utf-8`. `iconv` перекодирует: `-f` — из какой кодировки, `-t` — в какую.

# Коротко

- `.*` жадный; чтобы остановиться раньше, пишут `[^…]*`.
- «Или», `+` и скобки работают только с `grep -E` и `sed -E`.
- `grep -o` выводит только совпавший фрагмент.
- `sed -i.bak` правит файл и оставляет копию; сначала проверяют без `-i`.
- `awk 'условие {действие}'`; итоги считают в блоке `END`.
- Рейтинг: `sort | uniq -c | sort -rn | head`.
- Числа сортируют через `sort -n`, размеры — через `sort -h`.
- Для выровненного вывода — `awk`, а не `cut`.
- Имена файлов передают парой `-print0` и `xargs -0`.
- `^M` в ошибке означает окончания строк Windows; лечит `sed -i 's/\r$//'`.
