# Переменные

Переменная — это имя, за которым оболочка хранит строку. Создаётся она присваиванием, без пробелов вокруг знака равенства:

```
name=Linux
```

С пробелами получится другое: `name = Linux` оболочка поймёт как запуск программы `name` с двумя аргументами.

Чтобы получить значение, перед именем ставят знак `$`:

```
echo $name
echo "${name}_backup"
```

Фигурные скобки нужны, когда сразу за именем идут буквы: без них оболочка искала бы переменную `name_backup`.

# Окружение и export

Обычная переменная существует только внутри самой оболочки. Программы, которые вы запускаете, её не видят.

У каждого процесса есть **окружение** — набор переменных, который он получает от родителя при запуске и передаёт своим потомкам. Команда `export` переносит переменную в окружение:

```
EDITOR=vim
export EDITOR
```

или короче: `export EDITOR=vim`. Теперь её увидит, например, `git`, когда решит, какой редактор открыть.

Всё окружение целиком выводит команда `env`. В нём уже есть переменные, которые задала система:

- `HOME` — домашний каталог;
- `USER` — имя пользователя;
- `PWD` — текущий каталог;
- `PATH` — где искать программы, о нём ниже.

> И обычная переменная, и экспортированная живут до закрытия терминала. Чтобы переменная появлялась всегда, её записывают в файл `~/.bashrc`.

# Кавычки

Кавычки управляют тем, что оболочка делает со строкой до запуска программы.

```
name=Linux
echo '$name'
echo "$name"
```

Первая команда напечатает `$name`, вторая — `Linux`.

- **Одинарные** кавычки сохраняют всё буквально. Внутри них ничего не подставляется.
- **Двойные** кавычки сохраняют пробелы, но переменные и вложенные команды внутри них раскрываются.

Главная причина ставить двойные кавычки вокруг переменных — пробелы. Без кавычек оболочка разрежет значение на отдельные слова:

```
file="my report.txt"
rm $file
rm "$file"
```

Первая команда `rm` получит два аргумента — `my` и `report.txt` — и попытается удалить два разных файла. Вторая получит один, как и задумано.

# Подстановка команды

Конструкция `$(…)` выполняет команду и подставляет на своё место то, что она напечатала:

```
count=$(ls | wc -l)
echo "Файлов: $count"
```

Так результат одной команды становится аргументом другой или значением переменной.

# Три потока

У каждой программы есть три стандартных потока, у каждого свой номер:

- `0` — ввод (stdin), по умолчанию клавиатура;
- `1` — обычный вывод (stdout), по умолчанию экран;
- `2` — сообщения об ошибках (stderr), тоже экран.

На экране второй и третий выглядят одинаково, но перенаправляются по отдельности:

```
make > build.log
make 2> errors.log
make > build.log 2>&1
```

Первая строка отправляет в файл обычный вывод, ошибки остаются на экране. Вторая — наоборот. Третья собирает всё в один файл: запись `2>&1` означает «поток 2 направить туда же, куда сейчас направлен поток 1».

Ещё три полезных приёма:

- `команда 2> /dev/null` — отбросить ошибки: `/dev/null` поглощает всё, что в него пишут;
- `команда < файл` — подать файл на ввод;
- `команда | tee файл` — и показать вывод на экране, и сохранить его.

# Коды завершения

Каждая программа, завершаясь, возвращает число — код завершения. Ноль означает успех, любое другое число — ошибку. Код последней команды хранится в переменной `$?`:

```
ls /nope
echo $?
```

На коды опираются операторы `&&` и `||`:

```
mkdir build && cd build
ping -c 1 server || echo "сервер недоступен"
```

`&&` выполняет вторую команду при успехе первой, `||` — при неудаче. Вместе они заменяют короткое условие.

# PATH: как оболочка находит программы

Когда вы набираете `ls`, оболочка ищет файл с таким именем в каталогах, перечисленных в переменной `PATH`:

```
echo $PATH
```

Каталоги разделены двоеточиями и просматриваются по порядку. Что именно запустится, показывает `type ls`.

Текущего каталога в `PATH` нет. Поэтому скрипт, лежащий рядом, запускают с явным путём:

```
./deploy.sh
```

Просто `deploy.sh` оболочка будет искать только по `PATH` и ответит «command not found».

# Алиасы и ~/.bashrc

Алиас — короткое имя для длинной команды:

```
alias ll='ls -l'
```

Набранный в терминале, он исчезнет при его закрытии. Чтобы алиасы, переменные и другие настройки действовали всегда, их записывают в `~/.bashrc`: bash выполняет этот файл при открытии каждого нового терминала.

После правки файл можно перечитать, не открывая новое окно:

```
source ~/.bashrc
```

# Коротко

- Присваивание без пробелов: `name=value`. Чтение — через `$name`.
- `export` делает переменную видимой запускаемым программам.
- Одинарные кавычки — буквально, двойные — с подстановкой. Переменные с путями всегда берут в двойные кавычки.
- `$(команда)` подставляет вывод команды.
- Поток 1 — вывод, поток 2 — ошибки. `2>&1` объединяет их.
- Код завершения 0 — успех. Он лежит в `$?`, и на него смотрят `&&` и `||`.
- Программы ищутся по `PATH`; скрипт из текущего каталога запускают как `./имя`.
- Постоянные настройки оболочки живут в `~/.bashrc`.
