# Вход по ключу

Настройка входа без пароля состоит из двух действий.

```
ssh-keygen -t ed25519
ssh-copy-id anna@server
```

`ssh-keygen` создаёт пару ключей в `~/.ssh` и предлагает защитить закрытый ключ **парольной фразой**. Соглашаться стоит: с фразой украденный файл ключа бесполезен.

`ssh-copy-id` добавляет ваш открытый ключ в список разрешённых на сервере. Пароль учётной записи понадобится в последний раз. После этого `ssh anna@server` входит без него.

# Что где лежит

На вашем компьютере, в `~/.ssh`:

- `id_ed25519` — закрытый ключ;
- `id_ed25519.pub` — открытый ключ;
- `known_hosts` — ключи серверов, к которым вы уже подключались;
- `config` — ваши настройки клиента.

На сервере, в домашнем каталоге учётной записи:

- `~/.ssh/authorized_keys` — открытые ключи тех, кому разрешён вход под этой учётной записью, по одному в строке.

Именно в `authorized_keys` дописывает строку `ssh-copy-id`. Чтобы закрыть кому-то доступ, его строку из этого файла удаляют.

Файл `known_hosts` работает в обратную сторону: это не сервер проверяет вас, а вы — сервер. Если ключ сервера не совпал с сохранённым, `ssh` откажется подключаться.

# Права на ключ

`ssh` следит, чтобы закрытый ключ не мог прочитать никто, кроме владельца. Иначе он отказывается работать:

```
WARNING: UNPROTECTED PRIVATE KEY FILE!
Permissions 0644 for '/home/anna/.ssh/id_ed25519' are too open.
```

Такое случается, когда ключ скопировали с другого компьютера. Исправляется одной командой:

```
chmod 600 ~/.ssh/id_ed25519
```

Сам каталог `~/.ssh` должен иметь права 700.

# Агент: фраза один раз

Парольную фразу ключа пришлось бы вводить при каждом подключении. От этого избавляет **агент** — программа, которая держит расшифрованный ключ в памяти.

```
ssh-add
ssh-add -l
```

`ssh-add` спрашивает фразу один раз и передаёт ключ агенту. До конца сеанса работы `ssh` получает его оттуда. Ключ при этом остаётся защищённым на диске. `ssh-add -l` показывает, какие ключи сейчас в агенте.

# Настройки клиента: ~/.ssh/config

Длинные команды с портами, именами и ключами не нужно помнить. Их записывают в `~/.ssh/config`:

```
Host web
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_deploy
```

Теперь `ssh web` подключится к `203.0.113.10` на порт 2222 под пользователем `deploy` с указанным ключом. Тем же именем пользуются `scp` и `rsync`.

Блок `Host *` задаёт настройки для всех серверов сразу.

# rsync: передавать только изменения

Для повторной отправки больших каталогов `scp` неудобен: он каждый раз копирует всё заново. `rsync` сравнивает источник с приёмником и передаёт только то, что изменилось.

```
rsync -avz site/ anna@server:/var/www/site/
```

Ключи: `-a` — сохранять права, время и структуру каталогов; `-v` — показывать, что передаётся; `-z` — сжимать при передаче. Работает `rsync` поверх того же SSH, так что шифрование и ключи те же.

Косая черта в конце источника имеет значение: `site/` означает «содержимое каталога», `site` — «сам каталог».

# Настройки сервера: sshd_config

Сервером SSH управляет файл `/etc/ssh/sshd_config`. Его легко спутать с соседним `ssh_config` без буквы d — тот относится к клиенту.

Три настройки, которые меняют на любом сервере, доступном из интернета:

```
PermitRootLogin no
PasswordAuthentication no
Port 2222
```

- `PermitRootLogin no` запрещает входить сразу под root. Администраторы входят под своими учётными записями и повышают права через `sudo`: так видно, кто что делал.
- `PasswordAuthentication no` отключает вход по паролю, оставляя только ключи. Подбор пароля теряет смысл.
- `Port` меняет порт. Защитой это не является, но избавляет журнал от шума автоматических сканеров.

Изменения начинают действовать после `sudo systemctl reload ssh` (в Fedora и RHEL служба называется `sshd`).

> Отключать вход по паролю можно только после того, как вход по ключу проверен. Иначе вы закроете дверь перед самим собой.

# Когда не подключается

Причин отказа много, и сообщение клиента обычно короткое. Подробности показывает ключ `-v`:

```
ssh -v anna@server
```

`ssh` печатает каждый шаг: какой адрес и порт он пробует, какие файлы настроек читает, какие ключи предлагает и что отвечает сервер. По последним строкам видно, на чём всё остановилось. Ключи `-vv` и `-vvv` добавляют ещё подробностей.

# Коротко

- `ssh-keygen` создаёт пару, `ssh-copy-id` размещает открытый ключ на сервере.
- На сервере ключи лежат в `~/.ssh/authorized_keys`; у клиента ключи серверов — в `known_hosts`.
- Закрытому ключу нужны права 600, каталогу `~/.ssh` — 700.
- `ssh-add` отдаёт ключ агенту, и фразу не нужно вводить повторно.
- `~/.ssh/config` хранит имена, порты и ключи для коротких команд.
- `rsync -avz` передаёт только изменившееся.
- Сервер настраивают в `/etc/ssh/sshd_config`: `PermitRootLogin no`, `PasswordAuthentication no`.
- `ssh -v` показывает ход подключения.
