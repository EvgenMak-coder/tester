# Где остановилась загрузка

Незагружающаяся система почти всегда сообщает, на каком этапе она застряла. Узнав этап, вы сужаете поиск до одного-двух файлов.

- **Приглашение grub rescue** — застрял загрузчик.
- **«Kernel panic»** — ядро запустилось, но не смогло продолжить.
- **Аварийная оболочка с сообщением про emergency mode** — ядро и systemd работают, но не смонтировалось что-то из `/etc/fstab`.
- **Чёрный экран после списка служб** — система загрузилась, не стартовала графика.

# grub rescue

```
error: unknown filesystem.
grub rescue>
```

Начальная часть GRUB запустилась, но не нашла раздел со своими файлами — каталог `/boot/grub`. Обычные причины: раздел удалили, изменили его номер или размер, повредили файловую систему.

До ядра дело не дошло, поэтому изнутри системы это не починить. Загружаются с установочного носителя, подключают корневой раздел и переустанавливают загрузчик командами `grub-install` и `update-grub`.

# Паника ядра

```
Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0)
```

Сообщение исходит от ядра: оно работает, но не смогло подключить корневую файловую систему. `unknown-block(0,0)` означает, что ядро вообще не видит диск. Причин две:

- образ initramfs не создан, повреждён или не загружен, и драйвера диска у ядра нет;
- параметр `root=` указывает не на тот раздел.

Чаще всего это случается после неудачного обновления ядра, когда установка оборвалась раньше, чем был собран образ.

# Предыдущее ядро

Самый простой способ вернуть систему после неудачного обновления ядра — загрузить старое. Менеджер пакетов оставляет одно-два предыдущих ядра именно для этого.

В меню GRUB выбирают пункт «Advanced options» и в нём — предыдущую версию. Если меню не показывается, его вызывают, удерживая Shift или нажимая Esc сразу после включения.

Загрузившись со старым ядром, можно спокойно разобраться с новым: пересобрать его образ или удалить пакет.

# Пересобрать initramfs

```
sudo update-initramfs -u
sudo update-initramfs -u -k all
```

Первая команда пересобирает образ для самого нового ядра, вторая — для всех установленных. В Fedora и RHEL для этого служит `dracut -f`.

Пересборка нужна после изменений, которые должны подействовать на раннем этапе загрузки: правки в `/etc/modprobe.d`, смена настроек шифрования или LVM, добавление драйвера дискового контроллера.

# Загрузка в оболочку

Параметры ядра можно изменить разово, прямо в меню GRUB. Так сбрасывают забытый пароль root.

1. В меню выбрать пункт и нажать `e`.
2. Найти строку, начинающуюся со слова `linux`, и дописать в её конец `init=/bin/bash`.
3. Нажать Ctrl+X для загрузки.

Параметр `init=` заменяет первый процесс: вместо systemd ядро запускает оболочку с правами root, без запроса пароля. Корень при этом смонтирован только для чтения, поэтому сначала его перемонтируют:

```
mount -o remount,rw /
passwd root
```

Правка действует на одну загрузку и на диск не записывается.

> Вывод отсюда неприятный, но важный: физический доступ к компьютеру равен полному доступу. Защищает от этого только шифрование диска.

Более мягкий вариант — параметр `systemd.unit=rescue.target`: система загрузится в режим восстановления, но пароль root спросит.

# quiet и splash

По умолчанию ядру передаются параметры `quiet splash`: первый скрывает сообщения ядра, второй показывает заставку. Когда загрузка зависает, заставка мешает.

Если убрать эти слова — разово через `e` в меню или навсегда в `/etc/default/grub`, — на экране будут видны сообщения ядра и служб. Последняя строка перед зависанием обычно и называет виновника.

# Запретить модуль

Иногда модуль нужно не загружать вовсе: он конфликтует с другим драйвером или работает неправильно.

```
blacklist nouveau
```

Эту строку кладут в файл в каталоге `/etc/modprobe.d/`. После неё ядро не станет загружать модуль само при обнаружении устройства.

Затем образ initramfs пересобирают: иначе модуль успеет загрузиться из него на раннем этапе, до чтения файлов с диска. Команда `rmmod` выгружает модуль только до следующей загрузки.

# Secure Boot и подпись модулей

```
modprobe: ERROR: could not insert 'vboxdrv': Key was rejected by service
```

При включённом Secure Boot прошивка проверяет подпись загрузчика, загрузчик — ядра, а ядро принимает только подписанные модули. Модули из пакетов дистрибутива подписаны. Собранные на месте — драйверы видеокарт, VirtualBox — нет.

Решений два: подписать модуль собственным ключом и зарегистрировать этот ключ в прошивке через `mokutil` либо отключить Secure Boot.

# Системный раздел EFI

Прошивка UEFI не понимает ext4 и другие файловые системы Linux, но умеет читать FAT. Поэтому загрузчики лежат на отдельном небольшом разделе — **ESP**, отформатированном в FAT32.

В работающей системе он обычно смонтирован в `/boot/efi`. Внутри — по каталогу на каждую установленную систему, так что Linux и Windows на одном диске делят этот раздел. Список загрузочных записей прошивки показывает `efibootmgr`.

# sysctl и /proc/sys

Каждый параметр, который показывает `sysctl`, — это файл в каталоге `/proc/sys`. Точки в имени заменяют косые черты:

```
sysctl net.ipv4.ip_forward
cat /proc/sys/net/ipv4/ip_forward
```

Обе команды читают одно и то же. Запись в этот файл от имени root равносильна `sysctl -w`. Команда `sysctl` — лишь удобная обёртка, а настоящий интерфейс к настройкам ядра — файлы.

# Коротко

- По виду остановки определяют этап: `grub rescue>` — загрузчик, kernel panic — ядро, emergency mode — fstab.
- `grub rescue>` — GRUB не нашёл свой раздел; чинят с установочного носителя.
- «Unable to mount root fs» — нет initramfs или неверен `root=`.
- После неудачного обновления загружают предыдущее ядро из «Advanced options».
- `update-initramfs -u` пересобирает образ.
- `init=/bin/bash` в строке `linux` даёт оболочку root без пароля.
- Без `quiet splash` видно, на чём зависает загрузка.
- `blacklist имя` в `/etc/modprobe.d/` плюс пересборка initramfs запрещают модуль.
- «Key was rejected» — Secure Boot не принял неподписанный модуль.
- ESP — раздел FAT32 с загрузчиками, смонтирован в `/boot/efi`.
