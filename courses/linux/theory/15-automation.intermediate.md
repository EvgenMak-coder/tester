# Запись расписаний

В каждом из пяти полей cron можно писать не только число или звёздочку.

- **Шаг** — `*/15` в поле минут означает каждое значение с шагом 15: в 00, 15, 30 и 45 минут.
- **Диапазон** — `1-5` в поле дня недели означает с понедельника по пятницу.
- **Список** — `0,30` в поле минут означает в 00 и в 30.

```
*/15 * * * * /usr/local/bin/check.sh
0 9 * * 1-5 /usr/local/bin/report.sh
0 8,20 * * * /usr/local/bin/sync.sh
0 */6 * * * /usr/local/bin/rotate.sh
```

По порядку: каждые пятнадцать минут; в 9:00 по будням; в 8:00 и в 20:00; каждые шесть часов.

Легко ошибиться со звёздочкой в поле минут. Запись `* 2 * * *` означает не «в два часа ночи», а «каждую минуту с 2:00 до 2:59» — шестьдесят запусков. Для одного запуска в поле минут должно стоять число.

Для частых случаев есть сокращения: `@daily`, `@hourly`, `@weekly`, `@monthly` и `@reboot` — один раз при загрузке системы.

# Системные расписания

Кроме личных таблиц пользователей, у cron есть системные места.

- `/etc/crontab` и файлы в `/etc/cron.d/` — таблицы с дополнительным полем: после времени указывают, от чьего имени выполнять команду.
- `/etc/cron.hourly/`, `cron.daily/`, `cron.weekly/`, `cron.monthly/` — каталоги со скриптами. Всё, что в них лежит, запускается с соответствующей периодичностью.

Второй способ самый простой: положить исполняемый скрипт в `/etc/cron.daily/`, и он будет выполняться раз в сутки, без единой строки расписания.

В Debian и Ubuntu есть подвох: файлы с точкой в имени в этих каталогах молча пропускаются. Скрипт должен называться `backup`, а не `backup.sh`.

# anacron: для компьютеров, которые выключают

cron ничего не знает о пропущенном. Если ноутбук в три часа ночи был выключен, ночное задание просто не выполнится.

**anacron** работает иначе: он помнит дату последнего запуска каждого задания и после включения навёрстывает то, что пропущено. Точного времени он не обещает, его единица — сутки.

На большинстве систем каталоги `cron.daily`, `cron.weekly` и `cron.monthly` обслуживает именно anacron, поэтому ежедневные задания выполняются и на машинах, которые работают не круглосуточно.

# Сжатие в tar

У `tar` три буквы для трёх программ сжатия:

```
tar -czf site.tar.gz site
tar -cjf site.tar.bz2 site
tar -cJf site.tar.xz site
```

- `z` — gzip: быстро, сжатие умеренное. Выбор по умолчанию;
- `j` — bzip2: медленнее и плотнее;
- `J` — xz: сжимает заметно сильнее остальных, но работает медленнее и требует больше памяти.

Для ежедневных копий обычно берут gzip, для архивов, которые хранятся долго или скачиваются много раз, — xz.

Полезные дополнения: `-C каталог` распаковывает в указанное место, а `--exclude='*.log'` пропускает файлы по шаблону.

# rsync

`rsync` копирует каталоги, передавая только то, что изменилось. Это основной инструмент резервного копирования и синхронизации.

```
rsync -a site/ backup/
```

Ключ `-a` (архив) сохраняет права, владельцев, время изменения и символические ссылки и включает обход подкаталогов.

**Косая черта в конце источника меняет смысл**, и это самая частая ошибка:

```
rsync -a site/ backup/
rsync -a site backup/
```

Первая команда копирует **содержимое** `site`: файлы окажутся в `backup/`. Вторая копирует **сам каталог**: файлы окажутся в `backup/site/`.

# Зеркало и пробный запуск

По умолчанию `rsync` только добавляет и обновляет. Файл, удалённый в источнике, остаётся в приёмнике навсегда. Ключ `--delete` это меняет:

```
rsync -a --delete site/ backup/
```

Теперь из `backup` удаляется всё, чего больше нет в `site`, и получается точное зеркало. Но и ошибочное удаление в источнике при следующем запуске повторится в копии. А перепутанные местами аргументы уничтожат оригинал.

Поэтому перед запуском с `--delete` смотрят, что произойдёт:

```
rsync -a --delete --dry-run -v site/ backup/
```

`--dry-run`, коротко `-n`, проходит всю работу вхолостую и вместе с `-v` перечисляет файлы, которые были бы переданы и удалены. На диске ничего не меняется.

# Полные и инкрементные копии

**Полная копия** содержит все данные. Она велика и создаётся долго, зато для восстановления нужна только она.

**Инкрементная копия** содержит только то, что изменилось с прошлой копии. Она мала и создаётся быстро. Но для восстановления нужна последняя полная копия и вся цепочка инкрементных после неё. Потеря одного звена обрывает цепочку.

Обычная схема сочетает оба вида: полная копия раз в неделю, инкрементные каждый день. Так восстановление требует не больше семи шагов.

Зеркало, которое делает `rsync --delete`, — не то же самое, что история копий. В нём есть только последнее состояние, и файл, испорченный вчера, сегодня испорчен и в зеркале. Чтобы вернуться в прошлое, нужно хранить несколько копий за разные дни.

# Коротко

- `*/15` — шаг, `1-5` — диапазон, `0,30` — список; `@daily` и `@reboot` — готовые сокращения.
- Скрипт в `/etc/cron.daily/` выполняется раз в сутки; в Debian имя должно быть без точки.
- anacron навёрстывает задания, пропущенные из-за выключенного компьютера.
- В `tar`: `z` — gzip, `j` — bzip2, `J` — xz.
- `rsync -a источник/ приёмник/` копирует содержимое; без косой черты — сам каталог.
- `--delete` делает зеркало; перед ним — `--dry-run`.
- Инкрементная копия хранит только изменения и зависит от всей цепочки.
