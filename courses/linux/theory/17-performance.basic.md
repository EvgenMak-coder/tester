# «Сервер тормозит»

Жалоба «всё медленно» ничего не говорит о причине. Задача диагностики — превратить её в конкретный ответ: чего именно не хватает.

Почти любое замедление сводится к нехватке одного из четырёх ресурсов:

- **процессор** — программам не хватает вычислительного времени;
- **память** — данные не помещаются, и система уходит в подкачку;
- **диск** — программы ждут чтения и записи;
- **сеть** — данные медленно приходят или уходят.

Ресурс, который исчерпан первым и сдерживает всё остальное, называют **узким местом**. Суть в том, что ускорять что-либо другое бесполезно: если программа упёрлась в диск, более быстрый процессор ничего не изменит.

Поэтому порядок всегда один: сначала найти узкое место, потом что-то менять.

# Сколько ядер

```
nproc
```

Команда печатает число процессорных ядер. Это точка отсчёта для всех остальных цифр: нагрузку сравнивают с ним. Подробности о процессоре выводит `lscpu`.

# top

```
top
```

`top` показывает самые активные процессы и обновляет экран каждые несколько секунд. Сверху — сводка по системе, ниже — список процессов, отсортированный по нагрузке на процессор.

Столбцы, на которые стоит смотреть:

- `%CPU` — доля процессора, занятая процессом;
- `%MEM` — доля оперативной памяти;
- `RES` — сколько памяти процесс занимает на самом деле;
- `COMMAND` — что это за программа.

В `top` 100% соответствует **одному ядру**. Многопоточная программа на четырёх ядрах может показать до 400%. Значение 200 означает, что процесс полностью занимает два ядра.

Клавиши: `q` — выход, `M` — сортировать по памяти, `P` — снова по процессору, `1` — показать каждое ядро отдельно.

# htop

```
htop
```

`htop` делает то же, но нагляднее: цветные шкалы для каждого ядра и для памяти, прокрутка списка, управление мышью, подсказки по клавишам внизу. F5 показывает дерево процессов, F3 ищет, F9 отправляет сигнал выбранному процессу.

В большинстве дистрибутивов его нужно установить отдельно: `sudo apt install htop`.

# Память: как читать free

```
free -h
```

```
               total        used        free      shared  buff/cache   available
Mem:            15Gi       4.1Gi       0.3Gi       0.2Gi        11Gi        11Gi
Swap:          2.0Gi          0B       2.0Gi
```

Новичков пугает столбец `free`: свободно всего 0,3 ГБ из 15. Но это нормально.

Свободная память бесполезна, и ядро не оставляет её пустой. Оно хранит в ней копии недавно прочитанных файлов — это столбец **buff/cache**. Повторное обращение к тем же файлам идёт уже без диска. Как только память понадобится программам, кэш будет отдан мгновенно.

Смотреть нужно на столбец **available**: это оценка того, сколько памяти программы могут получить прямо сейчас. Здесь это 11 ГБ, и добавлять память не нужно.

Признак настоящей нехватки — малое значение `available` и растущее использование подкачки в строке Swap.

# Чем плоха подкачка

Когда память заканчивается, система начинает вытеснять данные программ на диск, в подкачку. Программы не завершаются, но каждое обращение к вытесненным данным требует чтения с диска.

Диск медленнее памяти в тысячи раз. Сервер, который активно обменивается с подкачкой, почти не отвечает: команды выполняются секундами, подключение по SSH длится минуту. Если всё вдруг стало очень медленным, а диск непрерывно занят, первым делом проверяют память.

# Диск: iotop

```
sudo iotop
```

`iotop` выглядит как `top`, но сортирует процессы по тому, сколько они читают и пишут на диск. Он отвечает на вопрос «кто грузит диск». Ему нужны права root.

Не путайте с `df` и `du`: те показывают, сколько места занято, а не кто сейчас работает с диском.

# Измерить время: time

```
time ./report.sh
```

`time` запускает команду и после её завершения печатает три числа:

```
real    0m12.340s
user    0m2.110s
sys     0m0.480s
```

- `real` — сколько времени прошло по часам;
- `user` — сколько процессорного времени ушло на саму программу;
- `sys` — сколько процессорного времени ядро потратило на её запросы.

Соотношение говорит о многом. Здесь программа работала 12 секунд, а процессор был занят меньше трёх. Остальное время она **ждала**: диск, сеть или другую программу. Ускорять её вычисления бессмысленно.

Если же `user` почти равен `real`, программа упирается в процессор.

# Коротко

- Замедление — это нехватка процессора, памяти, диска или сети; сначала находят узкое место.
- `nproc` — число ядер.
- `top` и `htop` показывают процессы и нагрузку; 100% в `%CPU` — одно ядро.
- В `free` смотрят на `available`, а не на `free`; `buff/cache` — кэш, который будет отдан.
- Активная работа с подкачкой резко замедляет всё.
- `iotop` показывает, кто грузит диск.
- `time команда`: если `real` намного больше `user` и `sys`, программа ждёт, а не считает.
