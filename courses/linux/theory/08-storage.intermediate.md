# От пустого диска к каталогу

Чтобы новый диск стал местом для файлов, нужно пройти три шага. Каждый делает своя программа.

1. **Разметить** — создать на диске разделы: `fdisk`.
2. **Создать файловую систему** на разделе: `mkfs`.
3. **Смонтировать** раздел в каталог: `mount`.

Перед каждым шагом сверяются с `lsblk`: все три команды разрушительны, если указать не то устройство.

# Разметка: fdisk

```
sudo fdisk /dev/sdb
```

`fdisk` работает в диалоге. Основные клавиши: `p` — показать таблицу разделов, `n` — создать раздел, `d` — удалить, `w` — записать изменения и выйти, `q` — выйти без записи. До нажатия `w` на диске ничего не меняется.

Аргументом служит диск целиком — `/dev/sdb`, а не раздел. Для дисков больше 2 ТБ и в автоматизации используют `parted`.

# Создание файловой системы: mkfs

```
sudo mkfs.ext4 /dev/sdb1
```

`mkfs` размечает раздел под файловую систему заново. Всё, что на нём было, пропадает; преобразования с сохранением файлов не бывает. Здесь аргумент — уже раздел, `/dev/sdb1`.

Создание раздела и создание файловой системы — разные действия. После `fdisk` раздел есть, но хранить в нём файлы ещё нельзя.

# Опознать раздел: blkid

```
sudo blkid /dev/sdb1
lsblk -f
```

`blkid` печатает тип файловой системы и **UUID** — уникальный идентификатор, записанный в самой файловой системе при её создании. `lsblk -f` показывает то же в виде таблицы для всех разделов.

# Постоянное монтирование: /etc/fstab

Команда `mount` действует до перезагрузки. Чтобы раздел подключался при каждой загрузке, его описывают в файле `/etc/fstab`, по строке на файловую систему:

```
UUID=3f1c9a2e-7b4d-4e0a-9c1f-2d5e8a6b0c11  /data  ext4  defaults  0 2
```

Поля идут в таком порядке: что монтировать, куда, тип файловой системы, параметры, и два числа в конце — о них на продвинутом уровне.

Раздел указывают по UUID, а не по имени вроде `/dev/sdb1`. Имена ядро раздаёт в порядке обнаружения дисков, и после перезагрузки или подключения нового диска `sdb` может стать `sdc`. UUID остаётся прежним.

# Проверить строку до перезагрузки

Ошибка в `fstab` обнаружится при следующей загрузке, и система может не подняться. Поэтому новую строку проверяют сразу:

```
sudo mount -a
findmnt /data
```

`mount -a` монтирует всё, что описано в `fstab` и ещё не смонтировано. Если в строке ошибка, она появится на экране сейчас. `findmnt` показывает, что каталог смонтирован и с какими параметрами.

Благодаря `fstab` работают и короткие команды: `mount /data` сам найдёт в файле устройство и параметры.

# Проверка: fsck

```
sudo fsck /dev/sdb1
```

`fsck` ищет и исправляет повреждения файловой системы после сбоев питания и ошибок диска.

> Запускать `fsck` можно только на размонтированной файловой системе. Пока раздел смонтирован, его структуры меняет ядро. Если одновременно их начнёт править `fsck`, данные будут испорчены.

Корневой раздел размонтировать на ходу нельзя, поэтому его проверяют при загрузке или загрузившись с другого носителя.

# LVM: гибкие тома

Обычный раздел трудно увеличить: рядом с ним на диске лежит следующий. **LVM** добавляет между дисками и файловыми системами прослойку, которая снимает это ограничение. В ней три уровня.

1. **Физический том** (PV) — диск или раздел, отданный LVM.
2. **Группа томов** (VG) — общий запас места, собранный из одного или нескольких физических томов.
3. **Логический том** (LV) — кусок из этого запаса. На нём создают файловую систему, как на обычном разделе.

```
sudo pvs
sudo vgs
sudo lvs
```

Эти три команды показывают состояние каждого уровня. Логические тома видны как `/dev/имя_группы/имя_тома`.

Преимущество в том, что логический том можно увеличить на ходу, пока в группе есть место, а в группу — добавить новый диск. Ещё LVM умеет делать снимки томов.

# tmpfs: файловая система в памяти

В выводе `df` есть строки с типом `tmpfs`:

```
tmpfs  795M  1.6M  793M  1% /run
```

Это файловая система, которая живёт в оперативной памяти. Она очень быстрая и не изнашивает диск, но всё её содержимое пропадает при перезагрузке. На ней держат служебные файлы текущего сеанса работы системы: `/run`, иногда `/tmp`.

# Коротко

- Три шага: разделы (`fdisk`), файловая система (`mkfs`), монтирование (`mount`).
- `mkfs` уничтожает содержимое раздела.
- `blkid` и `lsblk -f` показывают UUID и тип файловой системы.
- `/etc/fstab` описывает, что монтировать при загрузке; разделы указывают по UUID.
- Новую строку `fstab` проверяют командой `mount -a`.
- `fsck` запускают только на размонтированном разделе.
- LVM: физический том → группа томов → логический том.
- `tmpfs` хранит файлы в памяти до перезагрузки.
