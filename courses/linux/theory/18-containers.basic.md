# Зачем нужны контейнеры

Программе для работы нужно окружение: определённые версии библиотек, файлы настроек, другие программы. У разработчика на ноутбуке оно одно, на сервере — другое. Отсюда вечное «у меня работает».

Контейнер решает это так: программа упаковывается **вместе со всем своим окружением** и везде запускается одинаково. На сервер ставить для неё ничего не нужно, кроме программы для запуска контейнеров. Самая известная такая программа — Docker.

# Что такое контейнер

**Контейнер** — это обычный процесс, который ядро изолировало от остальной системы. У него:

- собственная файловая система: он видит только свои файлы;
- собственный список процессов: чужих он не видит;
- собственная сеть.

При этом ядро у контейнера общее с основной системой, которую называют **хостом**. Никакой второй операционной системы не загружается. Поэтому контейнер запускается за доли секунды и почти не тратит ресурсов на изоляцию.

# Контейнер и виртуальная машина

Изолировать программу можно и виртуальной машиной, но устроена она иначе.

- **Виртуальная машина** имитирует целый компьютер: виртуальный процессор, диск, сетевую карту. Внутри загружается полноценная операционная система со своим ядром.
- **Контейнер** использует ядро хоста и изолирует только процесс.

Отсюда различия. Виртуальная машина тяжелее: занимает гигабайты и загружается минуту, зато изолирована сильнее и может работать под другой системой — например, Windows на Linux. Контейнер легче и быстрее, но на Linux запускает только программы для Linux.

# Образ и контейнер

Два понятия, которые путают чаще всего.

**Образ** — неизменяемый шаблон: файловая система с программой, библиотеками и настройками по умолчанию. Образ — это файл, он ничего не делает.

**Контейнер** — запущенный экземпляр образа. Это уже работающий процесс.

Отношение то же, что между программой на диске и процессом. Из одного образа можно запустить сколько угодно контейнеров. Изменения, сделанные внутри контейнера, образ не затрагивают.

# Реестры и теги

Готовые образы хранятся в **реестрах**. Самый большой общедоступный — Docker Hub: в нём лежат официальные образы nginx, postgres, ubuntu и тысячи других. Когда реестр в имени образа не указан, Docker обращается туда.

```
docker pull ubuntu:24.04
docker images
```

`docker pull` скачивает образ. Часть после двоеточия — **тег**, метка конкретной версии. `docker images` показывает образы, которые уже есть на компьютере.

Если тег не указать, подставится `latest`. Это слово не означает «самая свежая версия»: это просто метка, которую автор образа двигает по своему усмотрению. Сегодня за ней одна версия, через месяц другая. В рабочих системах тег указывают явно.

# Запустить контейнер

```
docker run nginx
```

Команда создаёт контейнер из образа и запускает его. Если образа на компьютере нет, Docker сначала скачает его.

Каждый вызов `run` создаёт **новый** контейнер. Запустить уже существующий, остановленный контейнер — другая команда, `docker start`.

Контейнеру полезно дать имя, чтобы потом обращаться к нему по-человечески:

```
docker run --name web nginx
```

# Посмотреть, что запущено

```
docker ps
```

Команда показывает работающие контейнеры: идентификатор, образ, сколько времени работает, порты и имя. Остановленные в этот список не попадают.

# Журнал контейнера

```
docker logs web
docker logs -f web
```

`docker logs` показывает то, что программа в контейнере вывела на экран: в потоки stdout и stderr. Поэтому программы в контейнерах пишут журнал не в файл, а прямо в стандартный вывод: так его собирает Docker.

Ключ `-f` оставляет команду запущенной и показывает новые строки по мере появления.

# Остановить и удалить

```
docker stop web
docker rm web
```

`docker stop` просит программу в контейнере завершиться и ждёт. Контейнер при этом не исчезает: он остаётся на диске в остановленном состоянии, и его можно запустить снова.

`docker rm` удаляет остановленный контейнер совсем. Образ, из которого он был создан, остаётся; образы удаляет отдельная команда `docker rmi`.

# Коротко

- Контейнер — изолированный процесс со своей файловой системой, работающий на ядре хоста.
- Виртуальная машина имитирует компьютер и загружает собственное ядро; контейнер легче и быстрее.
- Образ — шаблон, контейнер — запущенный из него экземпляр.
- Образы берут из реестров, например Docker Hub; после двоеточия в имени — тег версии.
- `docker run образ` создаёт и запускает новый контейнер.
- `docker ps` — работающие контейнеры, `docker images` — скачанные образы.
- `docker logs имя` — вывод программы.
- `docker stop` останавливает, `docker rm` удаляет.
