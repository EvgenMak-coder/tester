# Задания по расписанию: cron

Многое на сервере должно происходить само и регулярно: резервная копия каждую ночь, очистка временных файлов раз в неделю, проверка раз в пять минут. Этим занимается служба **cron**. Раз в минуту она сверяется с таблицами расписаний и запускает то, чему пришло время.

У каждого пользователя своя таблица. Управляют ею командой `crontab`:

```
crontab -e
crontab -l
```

- `crontab -e` открывает таблицу в редакторе. После сохранения cron проверяет её и начинает использовать;
- `crontab -l` показывает таблицу, ничего не меняя.

> Рядом с ними есть ключ `-r`: он удаляет всю таблицу сразу и без подтверждения. На клавиатуре `r` стоит рядом с `e`, поэтому перед Enter стоит перечитать команду.

# Пять полей времени

Каждая строка таблицы — одно задание. Сначала идут пять полей, которые задают время, затем команда:

```
30 2 * * * /usr/local/bin/backup.sh
```

Поля по порядку, от мелкого к крупному:

1. минута (0–59);
2. час (0–23);
3. день месяца (1–31);
4. месяц (1–12);
5. день недели (0–7, где 0 и 7 — воскресенье, 1 — понедельник).

Звёздочка в поле означает «любое значение». Пример выше читается так: в 30 минут второго часа, в любой день любого месяца — то есть каждый день в 02:30.

Ещё несколько примеров:

```
0 9 * * 1 /usr/local/bin/report.sh
0 0 1 * * /usr/local/bin/monthly.sh
15 * * * * /usr/local/bin/check.sh
```

Первая строка — каждый понедельник в 9:00. Вторая — в полночь первого числа каждого месяца. Третья — каждый час на пятнадцатой минуте.

Команду в таблице пишут с полным путём: у cron короткий список каталогов для поиска программ.

# Один раз: at

cron повторяет задания. Чтобы выполнить команду один раз в назначенное время, есть `at`:

```
echo "/usr/local/bin/report.sh" | at 18:00
at now + 2 hours
```

`at` читает команды со стандартного ввода. Во втором случае он попросит ввести их с клавиатуры; ввод завершают сочетанием Ctrl+D.

Очередь заданий показывает `atq`, удаляет задание `atrm` с его номером.

# Архивы: tar

Чтобы сохранить или передать каталог целиком, его упаковывают в один файл — архив. В Linux для этого служит `tar`. У него три основных режима, и у каждого своя буква:

```
tar -cf backup.tar site
tar -tf backup.tar
tar -xf backup.tar
```

- `-c` — создать архив (create);
- `-t` — показать список файлов в нём (list);
- `-x` — извлечь файлы (extract).

Ключ `-f` всегда сопровождает их: сразу после него идёт имя файла архива. Перепутать порядок — частая ошибка: в команде `tar -cf backup.tar site` сначала архив, потом то, что в него положить.

Ключ `-v` добавляет к любому режиму перечисление обрабатываемых файлов.

Перед распаковкой чужого архива полезно заглянуть в него через `-t`: станет видно, что внутри и как записаны пути.

# Сжатие

Сам `tar` только склеивает файлы и места не экономит. Сжатие включают дополнительной буквой:

```
tar -czf site.tar.gz site
tar -xzf site.tar.gz
```

Буква `z` пропускает архив через программу gzip. Расширение `.tar.gz` — соглашение, по которому видно, что это сжатый архив.

При распаковке современный `tar` определяет сжатие сам, поэтому `tar -xf site.tar.gz` тоже сработает.

Отдельный файл сжимают командой `gzip` напрямую:

```
gzip big.log
gunzip big.log.gz
```

`gzip` заменяет файл его сжатой версией: появляется `big.log.gz`, а исходный `big.log` исчезает. Чтобы сохранить оригинал, добавляют ключ `-k`.

# Зачем нужны резервные копии

Данные теряют не только из-за поломки диска. Гораздо чаще причина — ошибка человека: удалили не тот каталог, запустили не тот скрипт, перезаписали файл. Ещё бывают сбои программ, кража, пожар, вирусы-шифровальщики.

Резервная копия — единственная защита от всего этого сразу. У неё три условия.

**Копия лежит отдельно от данных.** Копия на том же диске погибнет вместе с ним. Копия в соседнем каталоге не переживёт ни поломку диска, ни ошибочное удаление.

**Копия делается автоматически.** То, что нужно делать руками, однажды не будет сделано. Поэтому копирование поручают cron.

**Из копии умеют восстанавливать.** Копия, из которой ни разу не пробовали достать файл, — это надежда, а не резерв.

# Коротко

- cron выполняет команды по расписанию; таблицу правят через `crontab -e`, смотрят через `crontab -l`.
- Пять полей: минута, час, день месяца, месяц, день недели; `*` — любое значение.
- `at время` выполняет задание один раз.
- `tar -cf архив что` — создать, `-tf` — посмотреть, `-xf` — распаковать.
- `tar -czf` сжимает через gzip; `gzip файл` заменяет файл сжатым.
- Резервную копию хранят отдельно от данных, делают автоматически и проверяют восстановлением.
