# Два уровня: dpkg и apt

В Debian и Ubuntu с пакетами работают две программы, и у каждой своя роль.

**dpkg** — нижний уровень. Он умеет установить пакет из файла `.deb`, удалить его и ответить на вопросы об установленном. О репозиториях он ничего не знает и зависимости сам не скачивает.

**apt** — верхний уровень. Он работает с репозиториями: находит пакет, вычисляет зависимости, скачивает всё нужное и передаёт файлы `dpkg`.

Разница видна, когда пакет скачан вручную:

```
sudo dpkg -i program.deb
sudo apt install ./program.deb
```

Первая команда установит ровно этот файл и, если не хватает зависимостей, оставит пакет ненастроенным. Вторая сама скачает недостающее. Точка и косая черта обязательны: без них `apt` будет искать пакет с таким названием в репозитории.

В Fedora и RHEL та же пара называется `rpm` и `dnf`.

# Три способа удалить

```
sudo apt remove nginx
sudo apt purge nginx
sudo apt autoremove
```

- `remove` удаляет программу, но оставляет её настройки в `/etc` на случай, если её поставят снова.
- `purge` удаляет и настройки. Им пользуются, когда нужно начать с чистого листа.
- `autoremove` удаляет пакеты, которые когда-то были поставлены как зависимости и больше никому не нужны.

Файлы в домашних каталогах не трогает ни одна из этих команд.

Скачанные установочные файлы хранятся в кэше и со временем занимают заметное место. Его чистит `sudo apt clean`.

# upgrade и full-upgrade

`apt upgrade` никогда ничего не удаляет. Если новая версия пакета требует убрать другой пакет, она просто не ставится, и пакет остаётся старым.

`apt full-upgrade` такие случаи разрешает: при необходимости удаляет мешающие пакеты. Он нужен при переходе на новый выпуск дистрибутива и изредка — при обычных обновлениях. Список того, что будет удалено, стоит прочитать до подтверждения.

Посмотреть, что вообще готово к обновлению, ничего не меняя:

```
apt list --upgradable
```

# Вопросы об установленном

```
dpkg -l
dpkg -L nginx
dpkg -S /usr/bin/dig
```

- `dpkg -l` — список всех установленных пакетов с версиями;
- `dpkg -L пакет` — какие файлы принадлежат пакету;
- `dpkg -S файл` — какому пакету принадлежит файл.

Последняя выручает, когда программа есть на одном сервере и её нужно поставить на другой, а название пакета неизвестно: `dig`, например, приходит из пакета `bind9-dnsutils`.

# Откуда берутся пакеты

Список репозиториев лежит в двух местах:

- файл `/etc/apt/sources.list`;
- каталог `/etc/apt/sources.list.d/` — по файлу на каждый дополнительный репозиторий.

Сторонние репозитории принято добавлять отдельными файлами во второй каталог: так их легко найти и убрать. В новых версиях Ubuntu туда же переехал и основной список.

После правки этих файлов нужен `sudo apt update`, иначе `apt` не узнает о новых пакетах.

# Зафиксировать версию

Иногда обновление пакета нежелательно: от конкретной версии зависит рабочая система.

```
sudo apt-mark hold nginx
sudo apt-mark unhold nginx
apt-mark showhold
```

Удержанный пакет `apt upgrade` пропускает. Важно не забыть о нём: вместе с обычными обновлениями он перестаёт получать и исправления безопасности.

# Основные команды dnf и rpm

- `rpm -qa` — все установленные пакеты;
- `rpm -ql пакет` — файлы пакета;
- `rpm -qf файл` — какому пакету принадлежит файл;
- `sudo dnf install ./program.rpm` — установить файл вместе с зависимостями;
- `dnf repolist` — подключённые репозитории;
- `dnf check-update` — что можно обновить.

У `rpm` буква `q` означает запрос: все команды, начинающиеся с `-q`, только читают и ничего не меняют.

# snap и flatpak

Обычный пакет рассчитан на конкретный выпуск конкретного дистрибутива и использует системные библиотеки. У snap и flatpak другой подход: пакет несёт все зависимости с собой и работает в изоляции от остальной системы.

```
sudo snap install code --classic
flatpak install flathub org.gimp.GIMP
```

Преимущества: один пакет подходит для разных дистрибутивов, а свежая версия программы не зависит от возраста системы. Цена: больший размер, более медленный первый запуск и отдельный от `apt` механизм обновлений.

# Коротко

- `dpkg` работает с файлом пакета, `apt` — с репозиториями и зависимостями.
- Скачанный файл ставят так: `sudo apt install ./файл.deb`.
- `remove` оставляет настройки, `purge` удаляет и их, `autoremove` убирает ненужные зависимости.
- `full-upgrade` может удалять пакеты ради обновления, `upgrade` — никогда.
- `dpkg -S файл` — чей файл; `dpkg -L пакет` — что в пакете.
- Репозитории описаны в `/etc/apt/sources.list` и `/etc/apt/sources.list.d/`.
- `apt-mark hold` замораживает версию пакета.
- snap и flatpak несут зависимости с собой и работают изолированно.
