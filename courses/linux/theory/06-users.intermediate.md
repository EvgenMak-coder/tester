# Создать пользователя

```
sudo useradd -m -s /bin/bash boris
sudo passwd boris
```

`useradd` добавляет учётную запись. Два ключа нужны почти всегда:

- `-m` создаёт домашний каталог. Без него во многих дистрибутивах появится только строка в `/etc/passwd`, и пользователю некуда будет войти;
- `-s` задаёт оболочку.

Пароль `useradd` не устанавливает. Пока не выполнена `passwd boris`, войти по паролю нельзя.

В Debian и Ubuntu есть ещё команда `adduser`. Это надстройка над `useradd`: она сама создаёт каталог, спрашивает пароль и полное имя. Для создания людей вручную она удобнее, а в скриптах используют `useradd`.

# Изменить и удалить

```
sudo usermod -s /bin/zsh boris
sudo userdel -r boris
```

`usermod` меняет свойства существующей учётной записи теми же ключами, что у `useradd`.

`userdel` удаляет учётную запись. Ключ `-r` удаляет вместе с ней домашний каталог и почтовый ящик; без него каталог останется на диске. Файлы пользователя в других местах системы не затрагиваются в любом случае. Найти их можно по номеру бывшего владельца: `find / -uid 1001`.

# Основная и дополнительные группы

У пользователя одна **основная** группа: её получают файлы, которые он создаёт. Остальные группы — **дополнительные**, они только открывают доступ.

Добавляют пользователя в группу так:

```
sudo usermod -aG docker anna
```

> Ключ `-G` задаёт весь список дополнительных групп целиком. Без `-a` пользователь останется только в `docker` и потеряет все прочие группы, включая `sudo`.

Сама группа должна уже существовать. Создают её командой `groupadd`, а убрать пользователя из группы можно так: `sudo gpasswd -d anna docker`.

# Почему новая группа не работает сразу

Процесс получает список групп в момент входа пользователя и хранит его до завершения. Поэтому после `usermod -aG` в уже открытом терминале ничего не меняется: `id` показывает старый список, а команда `docker` по-прежнему отвечает «permission denied».

Нужно выйти из сеанса и войти заново. Перезагрузка для этого не требуется. Способ без выхода — `newgrp docker`: он запускает новую оболочку, где группа уже действует.

# Файл /etc/shadow

Файл `/etc/passwd` должен читаться всеми, поэтому пароли вынесены в отдельный файл — `/etc/shadow`. Читать его может только root. Буква `x` во втором поле `/etc/passwd` означает именно это: пароль хранится в shadow.

```
anna:$y$j9T$Qw1...:19990:0:99999:7:::
```

Второе поле — **хеш** пароля. Сам пароль не хранится нигде. Хеш вычисляется из пароля так, что обратно пароль из него не получить. При входе система вычисляет хеш введённого и сравнивает с сохранённым.

Начало хеша обозначает алгоритм: `$y$` — yescrypt, `$6$` — SHA-512.

Остальные поля — сроки: когда пароль меняли в последний раз, через сколько дней его нужно сменить, за сколько дней предупреждать.

# Заблокировать учётную запись

Когда доступ нужно закрыть временно, учётную запись не удаляют, а блокируют:

```
sudo passwd -l boris
sudo passwd -u boris
```

`passwd -l` ставит восклицательный знак перед хешем в `/etc/shadow`. После этого ни один введённый пароль не подойдёт. `passwd -u` снимает блокировку. Те же действия выполняют `usermod -L` и `usermod -U`.

Важная оговорка: блокируется именно пароль. Вход по ключу SSH может остаться доступным. Чтобы закрыть учётную запись целиком, задают дату окончания её действия:

```
sudo usermod --expiredate 1 boris
```

# Служебные учётные записи

Службы работают от имени отдельных учётных записей с малыми правами: `www-data`, `postgres`, `sshd`. Если такую службу взломают, взломщик получит только её права.

Входить под такими записями незачем, и это закрыто оболочкой:

```
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

`nologin` вместо оболочки означает: открыть интерактивный сеанс нельзя. При попытке входа программа печатает отказ и завершается. Процессы от имени этой записи при этом работают как обычно.

Выполнить команду от имени служебной учётной записи можно через `sudo` с ключом `-u`:

```
sudo -u postgres psql
```

Без ключа `-u` команда выполняется от root. Пароль спрашивается ваш.

# sudoers и visudo

Кому и что разрешено выполнять через `sudo`, записано в файле `/etc/sudoers`. Типичная строка выглядит так:

```
%sudo   ALL=(ALL:ALL) ALL
```

Она читается: участникам группы `sudo` (знак процента обозначает группу) на любом узле разрешено от имени любого пользователя выполнять любые команды.

Этот файл нельзя править обычным редактором. Если в нём окажется синтаксическая ошибка, `sudo` перестанет работать совсем, и исправить файл будет нечем. Для правки есть специальная команда:

```
sudo visudo
```

Она открывает файл в редакторе, не даёт править его двоим одновременно и перед сохранением проверяет синтаксис. Файл с ошибкой сохранить не получится.

Собственные правила принято класть не в сам файл, а в каталог `/etc/sudoers.d/`, по файлу на тему: `sudo visudo -f /etc/sudoers.d/deploy`.

Что разрешено вам, показывает `sudo -l`.

# Коротко

- `useradd -m` создаёт пользователя с домашним каталогом; пароль задаёт `passwd имя`.
- `userdel -r` удаляет учётную запись вместе с каталогом.
- `usermod -aG группа имя` добавляет в группу; без `-a` остальные группы пропадут.
- Новая группа начинает действовать после нового входа в систему.
- `/etc/shadow` хранит хеши паролей и сроки; читать его может только root.
- `passwd -l` блокирует пароль, `passwd -u` разблокирует; вход по ключу при этом может остаться.
- Оболочка `nologin` запрещает вход служебным учётным записям; `sudo -u имя` выполняет команду от их имени.
- `/etc/sudoers` правят только через `visudo`.
