# Права каталога — это другое

Буквы те же, но для каталога они означают иное, чем для файла. Каталог — это список имён, и права описывают действия с этим списком.

- `r` — читать список: видеть имена файлов. Это то, что нужно команде `ls`.
- `w` — менять список: создавать, удалять и переименовывать файлы внутри.
- `x` — проходить через каталог: входить в него командой `cd` и обращаться к файлам внутри по имени.

Право `x` — ключевое. Без него бесполезны остальные два: нельзя ни войти, ни открыть файл, даже зная его имя. Право `w` работает только вместе с `x`.

Встречаются два необычных сочетания:

- `--x` — список не виден, но файл с известным именем открыть можно;
- `r--` — имена видны, но ни войти, ни открыть файл нельзя.

# Почему удаление зависит от каталога

Удалить файл — значит убрать его имя из каталога. Поэтому проверяются права на каталог, а не на файл.

Отсюда следствие, которое удивляет: если у вас есть `w` и `x` на каталог, вы можете удалить в нём любой файл — чужой, принадлежащий root, закрытый от записи. Команда `rm` лишь переспросит, если файл защищён от записи.

И наоборот: право `w` на файл позволяет менять его содержимое, но не даёт его удалить.

# umask: права новых файлов

Права новых файлов задаёт не программа, которая их создаёт, а **маска** — число, показывающее, какие права нужно снять.

```
umask
```

Обычное значение — `022`. Расчёт идёт от базовых прав:

- для каталогов база 777;
- для файлов база 666: право на исполнение новым файлам не даётся никогда.

Маска убирает указанные в ней права:

- маска 022: каталоги получают 755, файлы — 644;
- маска 027: каталоги — 750, файлы — 640;
- маска 077: каталоги — 700, файлы — 600.

> Маска не вычитается как число, а снимает отдельные права. Добавить право, которого нет в базе, она не может.

Маска действует в пределах текущей оболочки. Чтобы она применялась всегда, её задают в `~/.bashrc`.

# Символьная запись chmod

Числовая запись задаёт все права разом. Символьная меняет только то, что названо, и остальное не трогает.

Она состоит из трёх частей: **кому**, **что сделать**, **какие права**.

- Кому: `u` — владелец, `g` — группа, `o` — остальные, `a` — все.
- Что сделать: `+` добавить, `-` отнять, `=` установить ровно такие.

```
chmod u+x deploy.sh
chmod go-rwx id_ed25519
chmod u=rw,go=r notes.txt
```

Вторая строка отнимает все права у группы и остальных, не трогая владельца. Так закрывают закрытый ключ SSH: если он доступен кому-то ещё, `ssh` откажется его использовать.

# Рекурсивное изменение

Ключ `-R` применяет команду к каталогу и ко всему, что в нём лежит:

```
sudo chown -R www-data:www-data /var/www/site
chmod -R go-w /srv/project
```

С числовыми правами `-R` опасен. `chmod -R 755` сделает исполняемыми все файлы, а `chmod -R 644` снимет `x` с каталогов, и войти в них будет нельзя. Каталогам и файлам нужны разные права.

Для этого у `chmod` есть заглавная `X`: она ставит право на исполнение только каталогам и тем файлам, которые уже исполняемые.

```
chmod -R u=rwX,go=rX site
```

# Три особых бита

Кроме девяти обычных прав, есть три особых. В выводе `ls -l` они занимают место буквы `x`.

**SUID** — буква `s` в тройке владельца:

```
-rwsr-xr-x 1 root root 59976 /usr/bin/passwd
```

Программа с таким битом выполняется с правами владельца файла, а не того, кто её запустил. Команда `passwd` принадлежит root, поэтому обычный пользователь через неё может изменить свой пароль в `/etc/shadow`, куда сам доступа не имеет.

**SGID** — буква `s` в тройке группы. На каталоге он означает: новые файлы получают группу каталога, а не основную группу создателя.

```
chmod g+s /srv/project
```

Так устраивают общие каталоги для совместной работы: всё созданное в них автоматически принадлежит группе проекта.

**Sticky bit** — буква `t` в конце:

```
drwxrwxrwt 18 root root 4096 /tmp
```

В каталоге с этим битом удалить или переименовать файл может только его владелец, владелец каталога или root. Без него в `/tmp`, куда писать разрешено всем, любой мог бы удалять чужие файлы.

В числовой записи особые биты — четвёртая цифра впереди: SUID = 4, SGID = 2, sticky = 1. Права `/tmp` записываются как 1777.

# Права символических ссылок

У символической ссылки права всегда показаны как `lrwxrwxrwx`, и они ни на что не влияют. Доступ определяется правами файла, на который ссылка ведёт, и каталогов на пути к нему. Команда `chmod`, применённая к ссылке, меняет права цели.

# Коротко

- Для каталога `r` — видеть имена, `w` — менять состав, `x` — входить и открывать файлы.
- Удаление файла определяется правами каталога, а не файла.
- `umask` снимает права с базы: 777 для каталогов, 666 для файлов.
- Символьная запись: кому (`u`, `g`, `o`, `a`), действие (`+`, `-`, `=`), права.
- Заглавная `X` при `-R` даёт вход в каталоги и не делает файлы исполняемыми.
- SUID — права владельца при запуске; SGID на каталоге — наследование группы; sticky bit — защита чужих файлов от удаления.
- Права самой символической ссылки не используются.
