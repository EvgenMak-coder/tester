# Сервер — это служба, которая слушает

Слово «сервер» означает и компьютер, и программу. В этом модуле речь о программах: это службы, которые ждут подключений по сети и отвечают на запросы. У каждой свой протокол и свой порт.

Самые распространённые виды сетевых служб стоит знать по именам, даже если вы не будете настраивать их сами:

- веб-сервер отдаёт сайты;
- сервер DNS превращает имена в адреса;
- файловый сервер открывает доступ к каталогам по сети;
- сервер времени синхронизирует часы;
- почтовый сервер принимает и пересылает письма.

# Веб-сервер

Веб-сервер принимает запросы браузеров и отвечает на них: отдаёт файл с диска — страницу, картинку, стиль — либо передаёт запрос приложению и возвращает его ответ.

В Linux чаще всего используют две программы:

- **nginx** — быстрый и экономный, сегодня самый распространённый;
- **Apache** — старейший, с огромным числом модулей.

Обе работают как службы systemd: `systemctl status nginx` покажет, запущен ли сервер.

# HTTP и HTTPS

Браузер и веб-сервер общаются по протоколу **HTTP**. У него два варианта:

- **HTTP** — без шифрования, порт **80**;
- **HTTPS** — тот же HTTP внутри защищённого соединения, порт **443**.

HTTPS даёт две вещи. Во-первых, обмен шифруется: посторонний в той же сети не прочитает и не подменит то, что передаётся. Во-вторых, проверяется подлинность сервера: браузер убеждается, что отвечает действительно владелец домена, а не кто-то, вставший посередине.

Сегодня HTTPS — норма. Сайт без него браузеры помечают как небезопасный.

# Сертификат

Подлинность сервера подтверждает **TLS-сертификат** — электронный документ, который связывает имя домена с открытым ключом сервера. Сертификат подписан удостоверяющим центром, которому доверяют браузеры.

К сертификату прилагается закрытый ключ. Сертификат открыт для всех, его получает каждый посетитель. Закрытый ключ остаётся на сервере и никому не передаётся.

У сертификата есть срок действия. Просроченный сертификат браузер отвергает с пугающим предупреждением, поэтому продление автоматизируют.

# Проверить веб-сервер

Когда сайт не открывается, первым делом выясняют, работает ли сам веб-сервер. Для этого запрос отправляют прямо с сервера:

```
curl http://localhost
curl -I http://localhost
```

Запрос к `localhost` не выходит за пределы машины. Ключ `-I` показывает только заголовки ответа, первая строка в них — код: 200 означает «всё в порядке».

Эта проверка делит задачу пополам. Если здесь ответ есть, а снаружи сайт не открывается, то веб-сервер работает, и искать нужно на пути к нему: в межсетевом экране, DNS или маршрутизации. Если ответа нет и здесь — проблема в самом веб-сервере.

# Общие каталоги: NFS и Samba

Чтобы несколько компьютеров работали с одними файлами, каталог открывают по сети. Способов два, и выбор зависит от того, кто будет подключаться.

**NFS** — родной способ для Linux и Unix. Сервер «экспортирует» каталог, клиент монтирует его в своё дерево и работает с файлами обычными командами, как с локальными.

**Samba** реализует протокол SMB, которым пользуется Windows. Сервер с Samba в проводнике Windows выглядит как обычный сетевой ресурс с общими папками.

Простое правило: между серверами Linux — NFS, для компьютеров с Windows — Samba.

# Точное время

Часы компьютера понемногу уходят. Для сервера это не мелочь:

- по времени сопоставляют записи в журналах разных машин;
- сертификаты проверяются по дате: при сбитых часах действующий сертификат кажется просроченным;
- системы входа и резервного копирования отказывают при расхождении в несколько минут.

Часы синхронизируют по сети с серверами точного времени, по протоколу **NTP**. В современных дистрибутивах этим занимается служба chrony или systemd-timesyncd.

```
timedatectl
```

Команда показывает текущее время, часовой пояс и главное — строку `System clock synchronized: yes`. Ею же меняют часовой пояс:

```
sudo timedatectl set-timezone Europe/Moscow
```

# Коротко

- Сетевая служба ждёт подключений на своём порту и отвечает по своему протоколу.
- Самые распространённые веб-серверы — nginx и Apache.
- HTTP — порт 80, HTTPS — порт 443; HTTPS шифрует обмен и подтверждает подлинность сервера.
- Сертификат связывает домен с открытым ключом и имеет срок действия.
- `curl http://localhost` на самом сервере проверяет, отвечает ли веб-сервер.
- NFS — общие каталоги между Linux, Samba — для Windows.
- Время синхронизируется по NTP; состояние показывает `timedatectl`.
