# Что такое служба

Большинство программ на сервере никто не запускает руками. Веб-сервер, сервер SSH, база данных, планировщик заданий стартуют при загрузке системы и работают в фоне, без окна и без участия пользователя. Такие программы называют **службами** или демонами.

За службами нужно следить: запускать в правильном порядке, перезапускать после сбоя, собирать их сообщения. В большинстве современных дистрибутивов этим занимается **systemd**. Это первый процесс, который запускает ядро, и от него происходят все остальные.

Управляют службами через одну команду — `systemctl`.

# Посмотреть состояние

```
systemctl status nginx
```

Это главная команда диагностики. В ответе несколько строк, и важны три из них:

```
● nginx.service - A high performance web server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled)
     Active: active (running) since Wed 2026-10-07 09:12:44; 3h ago
```

- **Loaded** — найдено ли описание службы и включён ли автозапуск: `enabled` или `disabled`;
- **Active** — работает ли служба прямо сейчас;
- в конце вывода — последние строки её журнала.

Значения в строке Active:

- `active (running)` — работает;
- `inactive (dead)` — не запущена. Ничего страшного в слове dead нет: служба просто остановлена;
- `failed` — запускалась и завершилась с ошибкой.

Для `status` права root обычно не нужны.

# Запустить, остановить, перезапустить

```
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
```

`start` запускает остановленную службу, `stop` останавливает работающую. `restart` делает то и другое подряд: его используют, чтобы служба перечитала изменённые настройки.

Эти команды меняют состояние всей системы, поэтому им нужен `sudo`.

Если всё прошло хорошо, `systemctl` ничего не печатает. Убедиться, что служба действительно запустилась, можно через `status`.

# Автозапуск

Запуск сейчас и запуск при загрузке — два независимых свойства.

```
sudo systemctl enable nginx
sudo systemctl disable nginx
```

`enable` включает автозапуск при загрузке системы. Саму службу он **не запускает**: она стартует только после следующей перезагрузки. `disable` отключает автозапуск и работающую службу не останавливает.

Отсюда четыре сочетания, и все они встречаются на практике:

- запущена и включена — обычное состояние рабочей службы;
- запущена, но не включена — работает до перезагрузки, потом не поднимется;
- остановлена, но включена — поднимется после перезагрузки;
- остановлена и отключена — не работает и не будет.

Самая частая ошибка новичка — запустить службу командой `start`, убедиться, что всё работает, и забыть про `enable`. После первой же перезагрузки сервера служба не поднимется.

# Журнал службы

Всё, что службы выводят, systemd собирает в общий журнал. Сообщения одной службы показывает `journalctl` с ключом `-u`:

```
journalctl -u nginx
journalctl -u nginx -f
```

Журнал открывается с самых старых записей и листается как в `less`: клавиша `G` переносит в конец, `q` закрывает. С ключом `-f` команда остаётся запущенной и показывает новые записи по мере появления.

# Порядок действий, когда служба не работает

1. `systemctl status имя` — работает ли она и что в последних строках журнала.
2. `journalctl -u имя` — если последних строк мало, полный журнал.
3. Исправить причину: чаще всего это ошибка в файле настроек или занятый порт.
4. `sudo systemctl restart имя` и снова `status`.

# Коротко

- Служба — программа, которая работает в фоне; службами управляет systemd.
- `systemctl status имя` — состояние и последние сообщения.
- `start`, `stop`, `restart` действуют сейчас.
- `enable` и `disable` управляют автозапуском и на текущее состояние не влияют.
- `inactive (dead)` — служба просто не запущена.
- `journalctl -u имя` — журнал одной службы, с `-f` — в реальном времени.
