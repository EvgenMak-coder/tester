# Адрес компьютера в сети

Чтобы компьютеры могли обмениваться данными, у каждого в сети должен быть **IP-адрес**. Адрес IPv4 — это четыре числа от 0 до 255 через точку: `192.168.1.15`.

```
ip addr
```

Команда показывает сетевые интерфейсы и их адреса. Интерфейс — это сетевое подключение: `lo` — внутренний, `eth0` или `enp3s0` — проводной, `wlan0` или `wlp2s0` — беспроводной. Адрес IPv4 стоит в строке `inet`.

У каждого интерфейса есть ещё **MAC-адрес** — аппаратный адрес, записанный в самом устройстве. В выводе он в строке `link/ether` и выглядит как шесть пар шестнадцатеричных цифр: `3c:52:82:4f:1a:9e`. По MAC-адресам устройства находят друг друга внутри локальной сети.

# Особые адреса

- **127.0.0.1**, он же `localhost` — этот самый компьютер. Пакеты на него не покидают машину.
- **Частные адреса** используются только внутри локальных сетей и в интернете не встречаются: `10.x.x.x`, `172.16.x.x`–`172.31.x.x` и `192.168.x.x`. Поэтому в разных домашних сетях адреса повторяются.

# Шлюз

Компьютер напрямую видит только соседей по своей локальной сети. Всё, что предназначено для остального мира, он отдаёт **шлюзу по умолчанию** — узлу, который пересылает пакеты дальше. Дома это роутер.

```
ip route
```

Строка, начинающаяся с `default via`, называет адрес шлюза.

# DHCP и DNS

Две службы делают сеть удобной, и их часто путают.

**DHCP** раздаёт настройки. Когда ноутбук подключается к Wi-Fi, сервер DHCP (дома — тот же роутер) выдаёт ему IP-адрес, адрес шлюза и адреса серверов DNS. Вручную ничего вводить не нужно.

**DNS** преобразует имена в адреса. Компьютеры связываются по IP-адресам, а люди пользуются именами вроде `ya.ru`. Перед каждым соединением система спрашивает у сервера DNS, какой адрес стоит за именем.

С именами связаны два файла:

- `/etc/hosts` — ручная таблица «адрес — имя». Строка `192.168.1.50 nas` позволит обращаться к узлу по имени `nas` без всякого DNS;
- `/etc/resolv.conf` — адреса серверов DNS, к которым обращается система.

Узнать адрес по имени вручную можно командой `nslookup ya.ru`. Имя своего компьютера печатает `hostname`.

# Проверка связи: ping

```
ping ya.ru
ping -c 4 8.8.8.8
```

`ping` отправляет узлу короткие запросы и показывает, пришёл ли ответ и за какое время. В Linux он работает без остановки: прерывают его сочетанием Ctrl+C, после чего он печатает итог — сколько пакетов отправлено и потеряно. Ключ `-c 4` ограничивает число запросов четырьмя.

Простая проверка, которая сразу отделяет одну неполадку от другой:

```
ping -c 1 8.8.8.8
ping -c 1 ya.ru
```

Если по адресу ответ есть, а по имени — ошибка `Temporary failure in name resolution`, значит интернет работает, а не работает DNS.

# Путь до узла: traceroute

```
traceroute ya.ru
```

Команда показывает цепочку маршрутизаторов, через которые идут пакеты, и время ответа каждого. По ней видно, на каком участке возникает задержка или обрыв.

# Порты

На одном компьютере работает много сетевых программ. Чтобы различать их, у каждой свой **порт** — число от 1 до 65535. Адрес говорит, на какой компьютер идёт соединение, порт — к какой программе.

Порты распространённых служб стоит помнить:

- 22 — SSH;
- 53 — DNS;
- 80 — HTTP;
- 443 — HTTPS.

Какие порты слушают программы на этом компьютере, показывает `ss`:

```
ss -tuln
```

Ключи: `-t` и `-u` — TCP и UDP, `-l` — только ожидающие подключений, `-n` — номера вместо названий.

# Скачать файл: wget и curl

```
wget https://example.com/file.zip
curl -O https://example.com/file.zip
curl -I https://example.com
```

`wget` скачивает файл и сохраняет его в текущем каталоге под тем же именем. `curl` без ключей выводит полученное прямо в терминал; сохранить файл его заставляет ключ `-O`.

`curl -I` запрашивает только заголовки ответа. Первая строка содержит код: 200 — всё в порядке, 404 — не найдено. Так быстро проверяют, жив ли сайт.

# Удалённый доступ

К терминалу другого компьютера подключаются по SSH, а файлы копируют командой `scp`:

```
ssh anna@server
scp report.pdf anna@server:/home/anna/
```

Соединение шифруется целиком, включая пароль. При первом подключении `ssh` спросит, доверяете ли вы ключу сервера: он видит его впервые. После ответа `yes` ключ запоминается, и вопрос больше не задаётся. Подробнее об этом — в модуле «SSH и удалённая работа».

# Коротко

- `ip addr` — адреса интерфейсов, `ip route` — шлюз по умолчанию.
- 127.0.0.1 — сам компьютер; адреса `192.168.x.x` и `10.x.x.x` — частные.
- DHCP раздаёт настройки, DNS превращает имена в адреса.
- `/etc/hosts` — ручные соответствия, `/etc/resolv.conf` — серверы DNS.
- `ping` проверяет связь, `traceroute` показывает путь.
- Порты: 22 — SSH, 53 — DNS, 80 — HTTP, 443 — HTTPS; `ss -tuln` показывает слушающие.
- `wget ссылка` скачивает файл, `curl -I ссылка` показывает заголовки ответа.
