# Когда файл удаляется на самом деле

Команда `rm` не стирает данные. Она убирает имя из каталога и уменьшает счётчик ссылок в inode. Данные освобождаются при двух условиях одновременно: имён не осталось и файл никем не открыт.

Из второго условия следует частая загадка: журнал на 20 ГБ удалили, а `df` показывает, что свободного места не прибавилось. Программа, которая писала в журнал, всё ещё держит его открытым. Имени у файла уже нет, но данные живы и продолжают расти.

Найти такие файлы помогает `lsof`:

```
sudo lsof +L1
```

Команда выводит открытые файлы, у которых не осталось имён, вместе с процессами, которые их держат. Место вернётся, когда процесс закроет файл: обычно после его перезапуска.

Если останавливать программу нельзя, файл обнуляют через её собственный дескриптор:

```
sudo truncate -s 0 /proc/1234/fd/5
```

# Как правильно очистить живой журнал

Отсюда правило: журнал работающей программы не удаляют, а обрезают.

```
truncate -s 0 app.log
```

`truncate` меняет размер файла, не трогая inode. Программа продолжает писать в тот же файл, а место освобождается сразу. После `rm app.log` она писала бы в невидимый файл, а созданный заново `app.log` остался бы пустым.

# Перенос: мгновенно или долго

Внутри одной файловой системы `mv` не трогает данные. Он добавляет имя в новый каталог и убирает из старого — правится только пара записей. Поэтому файл на 50 ГБ переезжает в соседний каталог мгновенно.

Между разными файловыми системами так сделать нельзя: inode одной не существует в другой. Тогда `mv` работает как копирование с последующим удалением оригинала, и время зависит от размера.

По той же причине жёсткая ссылка на другой раздел невозможна:

```
ln: failed to create hard link: Invalid cross-device link
```

Между разделами работает только символическая ссылка.

# Когда кончаются inode

Место на диске бывает двух видов: блоки под данные и inode под файлы. В ext4 число inode задаётся при создании файловой системы и потом не меняется.

Миллионы мелких файлов — сессии, кэш, письма — могут исчерпать inode раньше, чем блоки. Симптом выглядит странно:

```
No space left on device
```

при том, что `df -h` показывает свободные гигабайты. Проверяют это отдельным ключом:

```
df -i
```

Если в столбце `IUse%` стоит 100, новые файлы создать нельзя, сколько бы места ни оставалось. Помогает только удаление лишних файлов; найти каталог, где их больше всего, можно через `du --inodes`.

# Три отметки времени

В inode хранятся три отметки времени, и меняются они по разным поводам.

- **mtime** — время изменения содержимого. Его показывает `ls -l`.
- **ctime** — время изменения самого inode: прав, владельца, числа ссылок. Это не время создания.
- **atime** — время последнего чтения.

Запись в файл меняет mtime и вместе с ним ctime. Команды `chmod` и `chown` меняют только ctime: содержимое осталось прежним. Все три отметки выводит `stat`.

Отметку mtime можно выставить вручную командой `touch`, а ctime — нельзя. Поэтому при расследованиях смотрят именно на ctime.

# Разреженные файлы

У файла два размера: логический, который показывает `ls -l`, и занятое место, которое показывает `du`. Обычно они близки, но не всегда:

```
ls -lh disk.img
du -h disk.img
```

Первая команда может показать 10G, вторая — 4.0K. Такой файл называют разреженным: в нём есть участки, под которые место на диске не выделено. При чтении они выглядят как нули, а блоки появляются только там, куда действительно что-то записали.

Так устроены образы дисков виртуальных машин и файлы баз данных. Важно помнить об этом при копировании: программа, которая не знает о «дырах», запишет нули по-настоящему, и копия займёт полный объём. `cp` и `rsync` умеют сохранять разреженность: у `rsync` для этого есть ключ `--sparse`.

# find: действие над найденным

`find` умеет не только искать, но и выполнять команду над каждым найденным файлом. У действия `-exec` два окончания с разным поведением:

```
find . -name '*.tmp' -exec rm {} \;
find . -name '*.tmp' -exec rm {} +
```

С точкой с запятой `rm` запускается отдельно для каждого файла: тысяча файлов — тысяча запусков. С плюсом `find` собирает имена в длинные списки и передаёт их одной команде. Результат тот же, но второй вариант заметно быстрее.

Если нужно просто удалить найденное, есть готовое действие `-delete`.

# Имена, которые ломают команды

Имя файла может содержать почти любые символы: пробелы, переводы строк, дефис в начале. Два случая встречаются чаще других.

**Имя начинается с дефиса.** Файл с именем `-rf` программа `rm` примет за ключи. Кавычки и обратная косая черта не помогут: их снимает оболочка, и `rm` всё равно получит `-rf`. Есть два надёжных способа:

```
rm -- -rf
rm ./-rf
```

Два дефиса говорят программе, что ключи закончились и дальше идут только имена. Путь с `./` начинается уже не с дефиса.

**В имени есть пробелы.** Конвейер `find … | xargs rm` разрежет имя `old report.log` на два. Имена передают через нулевой байт, который в именах встретиться не может:

```
find . -name '*.log' -print0 | xargs -0 rm
```

# Путь в символической ссылке

Символическая ссылка хранит путь как текст. Если путь относительный, он отсчитывается от каталога, **в котором лежит сама ссылка**, а не от каталога, где вы стояли, когда её создавали.

```
ln -s ../shared/config.yml /opt/app/current/config.yml
```

Эта ссылка ведёт на `/opt/app/shared/config.yml`, откуда бы команду ни запустили. Частая ошибка — проверять относительный путь из своего текущего каталога, получить ответ «файл есть», а в итоге создать битую ссылку.

# Коротко

- Данные удаляются, когда нет ни имён, ни открывших файл процессов. Удалённые открытые файлы находит `lsof +L1`.
- Живой журнал обрезают через `truncate -s 0`, а не удаляют.
- `mv` внутри файловой системы мгновенен, между разными — копирует.
- «No space left» при свободном месте — проверьте `df -i`.
- mtime — содержимое, ctime — inode, atime — чтение.
- `ls -l` и `du` расходятся на разреженных файлах.
- `-exec … +` быстрее, чем `-exec … \;`.
- Имена с дефиса удаляют через `--` или `./`, имена с пробелами передают через `-print0` и `-0`.
- Относительный путь в ссылке отсчитывается от места, где лежит ссылка.
