# Расширение идёт снизу вверх

Хранилище устроено слоями: диск, на нём раздел или том LVM, на нём файловая система. Каждый слой не может быть больше того, на котором лежит, и ни один не растёт сам. Поэтому расширяют по порядку, от нижнего к верхнему.

**Диск виртуальной машины увеличили.** Раздел остался прежним, и сначала увеличивают его, а потом файловую систему:

```
sudo growpart /dev/sda 1
sudo resize2fs /dev/sda1
```

`growpart` растягивает раздел номер 1 на всё свободное место диска. `resize2fs` расширяет ext4 до размера раздела. Для XFS вместо неё используют `xfs_growfs` с точкой монтирования.

**Логический том увеличили.** Самая частая ошибка здесь — остановиться на полпути:

```
sudo lvextend -L +10G /dev/vg0/data
df -h /data
```

`df` покажет старый размер: вырос только том, файловая система о новом месте не знает. Нужен второй шаг — `resize2fs` или `xfs_growfs`. Ключ `-r` делает оба шага сразу:

```
sudo lvextend -r -L +10G /dev/vg0/data
```

# ext4 и XFS

Обе файловые системы надёжны и ведут журнал, но ведут себя по-разному при изменении размера.

- **ext4** можно увеличить на ходу, а уменьшить — только размонтировав.
- **XFS** увеличивается только в смонтированном виде, а уменьшить её нельзя совсем. Чтобы том стал меньше, данные переносят и создают файловую систему заново.

XFS лучше справляется с очень большими файлами и параллельной записью, поэтому её выбирают для хранилищ и баз данных. Но место под неё планируют с запасом в меньшую сторону: вырасти можно, сжаться — нет.

# Уровни RAID

RAID объединяет несколько дисков в один массив ради скорости, надёжности или того и другого.

- **RAID 0** — данные чередуются между дисками. Быстро, но отказ любого диска уничтожает всё.
- **RAID 1** — зеркало: на каждом диске полная копия. Переживает отказ всех дисков, кроме одного.
- **RAID 5** — данные и один блок чётности распределены по дискам. Переживает отказ одного диска.
- **RAID 6** — два блока чётности. Переживает отказ любых двух дисков.
- **RAID 10** — зеркала, собранные в чередование. Переживает один отказ наверняка, а два — только если диски из разных зеркал.

Программный RAID в Linux создаёт `mdadm`, а его состояние видно в `/proc/mdstat`.

> RAID защищает от поломки диска, но не от удалённого файла, ошибки в программе или шифровальщика. Резервную копию он не заменяет.

# Параметры монтирования

Четвёртое поле строки `fstab` — параметры через запятую. `defaults` означает обычный набор, к нему добавляют нужное.

- **nofail** — не считать ошибкой отсутствие устройства. Без него сервер, у которого отключён внешний диск из `fstab`, остановится при загрузке в аварийном режиме.
- **noatime** — не обновлять время последнего доступа при каждом чтении. Без него любое чтение файла вызывает запись на диск.
- **noexec** — запретить запуск программ с этой файловой системы.
- **ro** — только для чтения.
- **_netdev** — сетевая файловая система: монтировать после того, как поднимется сеть.

# Два числа в конце строки fstab

```
UUID=3f1c9a2e-…  /data  ext4  defaults,nofail  0 2
```

Пятое поле относится к устаревшей программе `dump` и почти всегда равно нулю.

Шестое задаёт порядок проверки `fsck` при загрузке: `0` — не проверять, `1` — проверять первой, это значение для корня, `2` — проверять после корня, для всех остальных.

# Резерв для root

На заполненном разделе ext4 обычные пользователи получают «No space left on device», а root продолжает писать. Причина в резерве: при создании ext4 оставляет часть блоков, обычно 5%, только для root.

Резерв нужен, чтобы системные службы и администратор могли работать даже на забитом диске, и чтобы файловая система меньше фрагментировалась. На корневом разделе он полезен. На разделе с данными в несколько терабайт 5% — это сотни гигабайт впустую, и его уменьшают:

```
sudo tune2fs -m 1 /dev/sdb1
```

# Только для чтения без причины

```
touch: cannot touch '/data/test': Read-only file system
```

Если раздел, который только что принимал запись, вдруг стал доступен только для чтения, это сделало ядро. ext4 обычно монтируют с параметром `errors=remount-ro`: обнаружив повреждение, ядро запрещает запись, чтобы не усугубить его.

Дальнейшие шаги:

1. `dmesg` — прочитать, что именно обнаружило ядро.
2. `smartctl -a /dev/sdb` — проверить здоровье самого диска.
3. Размонтировать раздел и запустить `fsck`.

Просто перемонтировать раздел обратно на запись — значит писать на повреждённую файловую систему.

# Подкачка и vm.swappiness

Когда памяти мало, у ядра есть выбор: сбросить файловый кэш или вытеснить в подкачку память программ. Параметр `vm.swappiness` задаёт, к чему оно склоняется.

```
sysctl vm.swappiness
sudo sysctl vm.swappiness=10
```

Обычное значение — 60. Чем меньше число, тем дольше ядро держит данные программ в памяти и тем позже трогает подкачку. На серверах баз данных его снижают до 1–10: обращение базы к странице, ушедшей на диск, стоит слишком дорого.

Размер и использование подкачки показывает `swapon --show`.

# Коротко

- Расширяют снизу вверх: раздел или том, затем файловая система.
- После `lvextend` нужен `resize2fs` или `xfs_growfs`; ключ `-r` делает это сам.
- XFS нельзя уменьшить; ext4 уменьшают только размонтированной.
- RAID 5 переживает один отказ, RAID 6 — два любых; RAID не заменяет резервную копию.
- `nofail` позволяет загрузиться без отсутствующего диска, `noatime` убирает лишние записи.
- Шестое поле `fstab` — порядок `fsck`: 0, 1 для корня, 2 для остальных.
- В ext4 около 5% блоков зарезервировано для root; меняется через `tune2fs -m`.
- Внезапное «Read-only file system» — ядро нашло ошибки: `dmesg`, `smartctl`, `fsck`.
- `vm.swappiness` определяет, насколько охотно ядро использует подкачку.
