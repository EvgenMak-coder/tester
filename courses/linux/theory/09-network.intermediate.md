# Сеть и её размер

Адрес состоит из двух частей: номер сети и номер узла в ней. Где проходит граница, показывает число после косой черты:

```
192.168.1.15/24
```

`/24` означает, что первые 24 бита из 32 — номер сети. На узлы остаётся 8 бит, то есть 256 адресов: от `192.168.1.0` до `192.168.1.255`. Два из них заняты: первый обозначает саму сеть, последний — широковещательный, «всем сразу». Узлам достаётся 254.

Чем меньше число после черты, тем больше сеть: `/16` — около 65 тысяч адресов, `/8` — около 16 миллионов.

Узлы одной сети общаются напрямую. Всё остальное идёт через шлюз.

# Соседи: ip neigh

Чтобы отправить пакет соседу по локальной сети, нужен его MAC-адрес. Система узнаёт его запросом ARP и запоминает:

```
ip neigh
```

Команда выводит таблицу соответствия IP-адресов и MAC-адресов соседних узлов. Состояние `REACHABLE` означает, что узел откликается, `FAILED` — что на запрос никто не ответил.

# Временные и постоянные настройки

Команда `ip` меняет состояние работающей системы:

```
sudo ip addr add 10.0.0.5/24 dev eth0
sudo ip link set eth0 up
sudo ip route add default via 10.0.0.1
```

Это действует сразу, но никуда не записывается. После перезагрузки или перезапуска сети всё вернётся к прежнему.

Постоянные настройки задают там, где сетью управляет система. Что это за место, зависит от дистрибутива:

- **Ubuntu Server** — файлы YAML в `/etc/netplan/`. Применяют их командой `sudo netplan apply`. На удалённом сервере безопаснее `sudo netplan try`: если не подтвердить изменения за две минуты, они откатятся сами.
- **Настольные системы, Fedora, RHEL** — NetworkManager. Им управляют командой `nmcli` или текстовым меню `nmtui`.

Команда `ip` при этом остаётся главным инструментом для проверки: она показывает то, что действует на самом деле.

# Кто слушает порты

```
sudo ss -tlnp
```

Ключ `-p` добавляет к каждому порту имя и номер процесса, поэтому нужен `sudo`. В выводе важно, на каком адресе программа слушает:

```
LISTEN 0 244 127.0.0.1:5432 0.0.0.0:* users:(("postgres",pid=812,fd=6))
LISTEN 0 511   0.0.0.0:80   0.0.0.0:* users:(("nginx",pid=901,fd=6))
```

- `127.0.0.1:5432` — служба принимает подключения только с этого же компьютера;
- `0.0.0.0:80` — со всех адресов, то есть и снаружи.

Это первое, что проверяют, когда служба «работает, но снаружи недоступна». Базу данных, к которой обращается только приложение на том же сервере, намеренно держат на `127.0.0.1`.

# TCP и UDP

Порты бывают двух видов, по числу транспортных протоколов.

**TCP** устанавливает соединение, подтверждает получение, повторяет потерянное и сохраняет порядок данных. На нём работает всё, где важна целостность: HTTP, SSH, почта, базы данных.

**UDP** просто отправляет пакеты, без соединения и подтверждений. Он быстрее и подходит для коротких запросов вроде DNS и там, где опоздавшие данные уже не нужны: звонки, видео, игры.

# Как система ищет имя

Когда программе нужен адрес по имени, система опрашивает несколько источников по очереди. Порядок записан в `/etc/nsswitch.conf`:

```
hosts: files dns
```

Сначала `files`, то есть `/etc/hosts`, затем DNS. Поэтому запись в `/etc/hosts` перекрывает то, что отвечает DNS.

В современных системах в `/etc/resolv.conf` часто стоит одна строка:

```
nameserver 127.0.0.53
```

Это не ошибка. По этому адресу слушает локальная служба `systemd-resolved`: она принимает запросы, сама обращается к настоящим серверам DNS и запоминает ответы. Какие серверы она использует, показывает `resolvectl status`.

# Отказ и молчание

Ошибки подключения бывают двух видов, и они указывают на разные причины.

```
curl: (7) Failed to connect to server port 8080: Connection refused
curl: (28) Failed to connect to server port 8080: Connection timed out
```

**Connection refused** — быстрый явный отказ. Пакеты дошли до узла, но на этом порту никто не слушает: служба не запущена или слушает другой порт или адрес.

**Connection timed out** — молчание. Ответа не было вовсе: узел выключен, к нему нет маршрута, либо межсетевой экран отбрасывает пакеты без ответа.

Первое чинят на самом сервере, второе ищут по пути к нему.

# Проверить порт: nc

`ping` показывает только, что узел жив. Доступен ли конкретный порт, проверяет `nc`:

```
nc -zv db.internal 5432
```

Ключ `-z` означает «только установить соединение и закрыть», `-v` — сообщить результат. Это самая быстрая проверка, когда приложение не может подключиться к базе или другому сервису.

# Коротко

- `/24` — 256 адресов, из них 254 для узлов.
- `ip neigh` — соответствие IP и MAC у соседей по сети.
- Команда `ip` меняет настройки до перезагрузки; постоянные задают в netplan или NetworkManager.
- `ss -tlnp` показывает слушающие порты и процессы; `127.0.0.1` — только локально, `0.0.0.0` — отовсюду.
- TCP гарантирует доставку, UDP — нет.
- Порядок поиска имён — в `/etc/nsswitch.conf`; `127.0.0.53` — локальная служба `systemd-resolved`.
- Refused — порт закрыт, timed out — ответа нет.
- `nc -zv узел порт` проверяет доступность порта.
