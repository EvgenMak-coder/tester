# Строгий режим

Надёжные скрипты начинаются с одной строки:

```
set -euo pipefail
```

В ней три независимые настройки, и у каждой своя задача.

**-e** — остановиться, как только команда завершится с ошибкой.

**-u** — считать ошибкой обращение к незаданной переменной. Без этого опечатка в имени превращается в пустую строку:

```
rm -rf "$BUILD_DIR/"*
```

Если переменная не задана, путь превратится в `/*`, и команда примется удалять всё от корня. С `set -u` скрипт остановится на этой строке с сообщением `unbound variable`, не дойдя до `rm`.

**pipefail** — считать конвейер неудачным, если с ошибкой завершилась любая его часть. Обычно код конвейера — это код последней команды, и сбой в середине остаётся незамеченным:

```
pg_dump db | gzip > db.gz
```

Без `pipefail` эта строка «успешна», даже если `pg_dump` упал: `gzip` исправно сжал пустоту.

# Где set -e не действует

На `set -e` нельзя полагаться полностью. В нескольких местах он отключён намеренно:

- в условии `if`, `while` и `until`;
- слева от `&&` и `||`;
- в команде после знака `!`.

Причина понятна: там ошибка — это не сбой, а ответ на вопрос. Но отключение распространяется на всё, что вызвано в таком месте, включая функцию целиком:

```
set -e
check() {
  false
  echo "после false"
}
if check; then
  echo ok
fi
```

Скрипт выведет «после false» и «ok». Внутри функции, вызванной в условии, `false` никого не останавливает, а код функции определяет её последняя команда — `echo`.

Вывод: важные шаги проверяют явно, а не надеются на `set -e`.

# Локальные переменные

Все переменные в `bash` по умолчанию общие для всего скрипта. Функция, которая присваивает `count`, меняет `count` у всех. В больших скриптах это источник трудноуловимых ошибок.

```
count=1
bump() {
  local count=5
}
bump
echo $count
```

Слово `local` создаёт переменную, которая живёт только внутри функции и заслоняет внешнюю с тем же именем. Пример выведет `1`. Все переменные внутри функций стоит объявлять через `local`.

# trap: убрать за собой

Скрипт, создающий временные файлы, должен удалять их при любом исходе: после успеха, после ошибки, после Ctrl+C. Для этого есть `trap`:

```
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT
```

Команда, назначенная на `EXIT`, выполняется при выходе из скрипта, каким бы он ни был: после последней строки, по `exit`, при остановке из-за `set -e`. Одинарные кавычки важны: переменная подставится в момент срабатывания, а не объявления.

Вместо `EXIT` можно назвать сигнал: `trap 'echo прервано; exit 130' INT` перехватит Ctrl+C.

# Массивы

Когда значений несколько и в них могут быть пробелы, обычная строка не годится. Массив хранит элементы отдельно:

```
files=(a.txt "b c.txt" d.txt)
echo ${#files[@]}
echo "${files[0]}"
for f in "${files[@]}"; do
  echo "$f"
done
```

- `${#files[@]}` — число элементов, здесь 3;
- `${files[0]}` — первый элемент, счёт с нуля;
- `"${files[@]}"` — все элементы, каждый отдельным словом;
- `files+=(e.txt)` — добавить элемент.

Кавычки вокруг `"${files[@]}"` обязательны по той же причине, что и вокруг `"$@"`.

Массивом удобно собирать команду по частям: `args=(-a --delete)`, затем `rsync "${args[@]}" src/ dst/`.

# Подоболочки и конвейеры

Каждая часть конвейера выполняется в отдельной копии оболочки. Переменные, изменённые там, наружу не возвращаются:

```
n=0
printf 'a\nb\nc\n' | while read -r x; do
  n=$((n + 1))
done
echo $n
```

Будет выведен `0`. Цикл трижды увеличил собственную копию `n`, и она исчезла вместе с подоболочкой.

Исправляют это, подавая данные не конвейером, а перенаправлением:

```
while read -r x; do
  n=$((n + 1))
done < <(printf 'a\nb\nc\n')
```

Теперь цикл выполняется в основной оболочке, и `n` станет равно 3.

# Двойные квадратные скобки

У `bash` есть улучшенная форма проверки — `[[ … ]]`. Она безопаснее: переменные внутри не разбиваются на слова, и кавычки вокруг них не обязательны. Ещё она умеет сравнивать с шаблоном:

```
if [[ "$file" == *.log ]]; then
  echo "это журнал"
fi
```

Правая часть без кавычек — шаблон. Условие проверяет, заканчивается ли значение переменной на `.log`. Файлы на диске при этом не затрагиваются: шаблон сравнивается со строкой и в имена файлов не раскрывается.

Если шаблон взять в кавычки, сравнение станет буквальным. Оператор `=~` сравнивает с регулярным выражением.

# Обработка строк без внешних программ

`bash` умеет резать строки сам, без `basename`, `dirname` и `sed`:

```
f=/var/log/app.log
echo "${f##*/}"
echo "${f%/*}"
echo "${f%.log}"
```

Вывод — `app.log`, `/var/log` и `/var/log/app`.

- `#` удаляет шаблон с начала строки, `%` — с конца.
- Один знак удаляет самое короткое совпадение, два — самое длинное.

Запомнить стороны помогает клавиатура: `#` стоит левее `%`.

Ещё две полезные формы: `${#f}` — длина строки, `${f/log/txt}` — замена первого совпадения.

# Here-документ

Многострочный текст передают команде конструкцией `<<`:

```
cat <<EOF > /etc/app/config
user=$USER
home=$HOME
EOF
```

Строки до слова-ограничителя идут на ввод команды. Переменные и `$(…)` внутри подставляются.

Если ограничитель взять в кавычки, текст передаётся как есть:

```
cat <<'EOF'
Привет, $name
EOF
```

Будет напечатано `Привет, $name`. Эту форму используют, когда записывают скрипт или шаблон, в котором знаки доллара должны остаться.

# Проверка скриптов

Большинство описанных здесь ошибок находит программа `shellcheck`:

```
shellcheck deploy.sh
```

Она укажет на переменные без кавычек, бесполезные конструкции и места, где скрипт поведёт себя не так, как задумано. Прогонять через неё каждый скрипт — самая выгодная привычка в написании на `bash`.

# Коротко

- `set -euo pipefail`: остановка при ошибке, при незаданной переменной и при сбое в конвейере.
- В условиях и после `&&` и `||` режим `set -e` не действует, в том числе внутри вызванных там функций.
- `local` ограничивает переменную функцией.
- `trap 'команда' EXIT` выполняется при любом завершении.
- Массив: `arr=(a b)`, `${#arr[@]}`, `"${arr[@]}"`.
- Переменные, изменённые в конвейере, теряются; данные подают через `< <(команда)`.
- `[[ $x == шаблон ]]` сравнивает строку с шаблоном.
- `${f##*/}` — имя файла, `${f%/*}` — каталог, `${f%.log}` — без расширения.
- `<<'EOF'` передаёт текст без подстановок.
