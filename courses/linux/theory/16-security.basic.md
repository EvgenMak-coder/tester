# С чего начинается безопасность

Сервер, подключённый к интернету, начинают проверять на прочность через несколько минут после включения. Это делают не люди, а автоматические программы, которые перебирают адреса подряд. Им всё равно, чей это сервер и что на нём лежит.

Хорошая новость в том, что подавляющее большинство таких атак отбивается несколькими простыми мерами. Этот раздел — о них.

# Наименьшие привилегии

Главный принцип безопасности: каждый пользователь и каждая программа получает ровно столько прав, сколько нужно для работы, и не больше.

Смысл простой. Ошибка или взлом причиняют вред в пределах прав того, с кем они случились. Взломанный веб-сервер, работающий от отдельной учётной записи, может испортить свои файлы. Тот же веб-сервер, работающий от root, отдаёт взломщику всю систему.

Из этого принципа следует почти всё остальное: отдельные учётные записи для служб, права на файлы, `sudo` вместо общего пароля root.

# Не работать под root

На root не действуют проверки прав. Поэтому постоянная работа под ним опасна вдвойне:

- любая опечатка действует на всю систему. Лишний пробел в `rm -rf` обычному пользователю грозит потерей своих файлов, а root — потерей сервера;
- любая программа, которую вы запустили, получает те же неограниченные права. В том числе вредоносная.

Правильный порядок — входить под своей учётной записью и повышать права через `sudo` только для тех команд, которым это нужно. Заодно в журнале остаётся запись, кто и что выполнял.

# Обновления

Большинство взломов происходит через уязвимости, для которых исправление давно выпущено. После выхода исправления описание уязвимости становится общедоступным, и необновлённые системы начинают атаковать автоматически.

```
sudo apt update
sudo apt upgrade
```

Регулярное обновление — самая дешёвая и самая действенная мера защиты. На серверах его обычно автоматизируют, об этом рассказывает средний уровень.

# Межсетевой экран

**Межсетевой экран** (firewall) решает, какие сетевые соединения пропустить, а какие заблокировать. Правила опираются на адреса, порты и протоколы.

Обычная настройка сервера: все входящие соединения запрещены, кроме нескольких явно разрешённых портов. Тогда служба, которую вы запустили для проверки и забыли выключить, снаружи недоступна.

В Ubuntu экраном управляет простая программа `ufw`:

```
sudo ufw status
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

- `status` показывает, включён ли экран и какие правила заданы;
- `allow 22/tcp` разрешает входящие подключения на порт 22 по протоколу TCP — это SSH;
- `enable` включает экран сейчас и при каждой загрузке.

Обратное действие к `allow` — `deny`.

> Настраивая экран на удалённом сервере, сначала разрешите SSH и только потом включайте экран. Иначе вы закроете дверь, через которую вошли.

# Ключи вместо паролей

Пароль к SSH на сервере в интернете подбирают круглосуточно. Сложный пароль замедляет подбор, но не отменяет его.

Вход по ключу устраняет саму возможность: ключ нельзя угадать перебором. Самая действенная мера защиты SSH — настроить вход по ключам и отключить вход по паролю совсем.

Смена стандартного порта 22 на другой защитой не является: сканеры находят SSH на любом порту. Она лишь уменьшает число записей в журнале.

# Защита от подбора: fail2ban

Пока вход по паролю остаётся, помогает программа `fail2ban`. Она читает журналы, находит в них повторяющиеся неудачные попытки входа с одного адреса и на время блокирует этот адрес в межсетевом экране.

Для атакующего это превращает подбор из тысяч попыток в минуту в несколько попыток в час.

# Шифрование диска

Права доступа действуют, только пока работает система, которая их проверяет. Если диск вынуть и подключить к другому компьютеру, все файлы читаются без всяких паролей.

**Шифрование диска** защищает именно от этого. Без ключа содержимое зашифрованного диска — бессмысленный набор байтов. Оно нужно прежде всего ноутбукам и всему, что могут украсть или потерять.

Чего шифрование не даёт: оно не защищает работающую систему от вирусов и взлома по сети и не спасает данные при поломке диска. Для второго нужна резервная копия.

# SELinux и AppArmor

Обычные права смотрят только на пользователя: всё, что разрешено пользователю, разрешено любой программе, которую он запустил.

SELinux и AppArmor добавляют второй слой: они ограничивают, к чему может обращаться **каждая программа**. Веб-серверу разрешено читать каталог сайта и писать в свой журнал, и ничего больше. Даже взломанный и даже работающий от root, он не прочитает чужие каталоги.

SELinux используется в Fedora и RHEL, AppArmor — в Ubuntu и Debian. Обе системы включены по умолчанию, и отключать их «чтобы заработало» — плохая привычка.

# Коротко

- Наименьшие привилегии: каждому — только необходимые права.
- Под root не работают постоянно; права повышают через `sudo`.
- Обновления закрывают известные уязвимости.
- Межсетевой экран пропускает только разрешённые соединения; в Ubuntu — `ufw`.
- Перед `ufw enable` на удалённом сервере разрешают SSH.
- Вход по ключам надёжнее любого пароля; `fail2ban` блокирует адреса с подбором.
- Шифрование диска защищает данные при краже устройства.
- SELinux и AppArmor ограничивают каждую программу отдельно.
