# Проверки

Квадратные скобки в условии — это команда проверки. У неё три группы операторов.

**Файлы:**

- `-e путь` — существует;
- `-f путь` — существует и это обычный файл;
- `-d путь` — существует и это каталог;
- `-s путь` — файл не пуст;
- `-x путь` — есть право на исполнение.

**Строки:**

- `"$a" = "$b"` — равны;
- `"$a" != "$b"` — не равны;
- `-z "$a"` — пустая;
- `-n "$a"` — не пустая.

**Числа:**

- `-eq` — равно, `-ne` — не равно;
- `-lt` — меньше, `-le` — меньше или равно;
- `-gt` — больше, `-ge` — больше или равно.

```
if [ -f "$path" ]; then
  echo "файл есть"
fi
```

Для чисел и строк операторы разные, и это важно:

```
a=010
b=10
[ "$a" = "$b" ] && echo строки
[ "$a" -eq "$b" ] && echo числа
```

Будет выведено только слово «числа». Как строки `010` и `10` различаются, как числа — равны.

Переменные в проверках всегда берут в двойные кавычки. Без них пустая переменная исчезнет из строки, и проверка сломается с непонятной ошибкой.

# Все аргументы сразу

Чтобы перебрать все аргументы скрипта, используют `"$@"` — обязательно в кавычках:

```
for f in "$@"; do
  echo "$f"
done
```

`"$@"` раскрывается в отдельное слово на каждый аргумент, сохраняя пробелы внутри. Если скрипт запущен как `./run.sh "my file.txt" notes.txt`, цикл выполнится два раза. Без кавычек имя с пробелом распалось бы на два слова, и проходов было бы три.

# Значения по умолчанию

```
port=${PORT:-8080}
name=${1:-guest}
```

Запись `${имя:-значение}` подставляет значение переменной, а если она пуста или не задана — то, что после `:-`. Сама переменная при этом не меняется.

Так делают необязательными аргументы и настройки: скрипт работает без них, но позволяет их переопределить.

# Арифметика

Обычное присваивание работает со строками. Для вычислений нужны двойные круглые скобки:

```
x=5
echo $((x * 2 + 1))
count=$((count + 1))
```

Первая строка вывода — `11`: приоритет операций обычный, сначала умножение. Внутри скобок переменные можно писать без знака `$`. Арифметика целочисленная: `$((7 / 2))` даст 3.

# Цикл while и чтение файла

Цикл `while` повторяется, пока условие истинно. Самое частое его применение — построчное чтение файла:

```
while read -r line; do
  echo "> $line"
done < servers.txt
```

Перенаправление после `done` подаёт файл на ввод всему циклу. `read` забирает по одной строке за проход, а когда строки кончаются, возвращает ошибку, и цикл завершается. Ключ `-r` запрещает особую обработку обратной косой черты: без него такие символы в данных пропадают.

# Выбор: case

Когда значение нужно сравнить с несколькими вариантами, `case` читается лучше цепочки `if`:

```
case "$1" in
  start)   echo "запуск" ;;
  stop)    echo "остановка" ;;
  *.log)   echo "это журнал" ;;
  *)       echo "неизвестная команда"; exit 1 ;;
esac
```

Значение сравнивается с шаблонами по порядку, и выполняется первая подошедшая ветка. В шаблонах работают те же знаки, что в именах файлов. Шаблон `*` подходит ко всему, поэтому его ставят последним как вариант «иначе». Каждая ветка заканчивается двумя точками с запятой.

# Функции

Повторяющийся кусок кода оформляют функцией:

```
greet() {
  echo "Привет, $1"
}

greet Анна
greet Борис
```

Функцию вызывают как обычную команду. Внутри неё `$1`, `$2` и `$#` относятся к аргументам **функции**, а не скрипта.

Функция возвращает код завершения: по умолчанию — код своей последней команды, явно — через `return 1`. Поэтому её можно использовать в условии: `if check_disk; then …`.

# Остановиться при ошибке: set -e

По умолчанию `bash` продолжает выполнять скрипт после сбоя. Это опасно:

```
cd /var/www/site
rm -rf cache
```

Если каталога нет, `cd` завершится ошибкой, а `rm` всё равно выполнится — в том каталоге, где скрипт оказался.

```
set -e
```

Эта строка в начале скрипта меняет поведение: скрипт прекращается, как только любая команда вернёт ненулевой код.

# Отладка: bash -x

Когда скрипт делает не то, проще всего посмотреть, какие команды он на самом деле выполняет:

```
bash -x deploy.sh
```

Перед выполнением каждой команды `bash` печатает её со знаком плюс в начале и с уже подставленными значениями переменных. Сразу видно, что переменная пуста или в путь попал лишний пробел.

Ещё один полезный ключ — `bash -n deploy.sh`: он проверяет синтаксис, ничего не выполняя.

# Коротко

- Проверки: `-f` файл, `-d` каталог, `=` для строк, `-eq`, `-lt`, `-gt` для чисел.
- Переменные в проверках — в двойных кавычках.
- `"$@"` — все аргументы, каждый отдельным словом.
- `${имя:-значение}` — значение по умолчанию.
- `$(( … ))` — целочисленная арифметика.
- `while read -r line; do … done < файл` читает файл построчно.
- `case` сравнивает с шаблонами, `*` — ветка «иначе».
- В функции `$1` — её собственный аргумент.
- `set -e` останавливает скрипт при первой ошибке, `bash -x` показывает выполняемые команды.
