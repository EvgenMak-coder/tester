# Зачем читать журналы

Программы в Linux редко показывают окно с ошибкой. Вместо этого они записывают происходящее в **журналы**: что запустилось, кто вошёл, что пошло не так. Когда что-то не работает, ответ почти всегда уже записан — нужно знать, где искать.

В современных системах журналы хранятся в двух местах: в текстовых файлах в каталоге `/var/log` и в журнале systemd.

# Каталог /var/log

```
ls /var/log
```

Здесь лежат текстовые файлы, которые ведут система и службы. Самые полезные в Debian и Ubuntu:

- `syslog` — общий журнал системы;
- `auth.log` — входы в систему, в том числе по SSH, и каждое использование `sudo`;
- `kern.log` — сообщения ядра;
- `dpkg.log` — установка и удаление пакетов;
- каталоги служб: `nginx/`, `apt/` и другие.

В Fedora и RHEL общий журнал называется `messages`, а журнал входов — `secure`.

Многие из этих файлов может читать только root или участник группы `adm`, поэтому команды обычно идут с `sudo`.

# Смотреть файл журнала

Журнал — обычный текст, и работают с ним обычными командами:

```
sudo less /var/log/syslog
sudo tail -n 50 /var/log/auth.log
sudo grep "Failed password" /var/log/auth.log
```

Свежие записи находятся в конце, поэтому чаще всего нужен `tail`. Его режим слежения незаменим при поиске ошибки:

```
sudo tail -f /var/log/syslog
```

Команда показывает новые строки по мере появления. В одном окне запускают её, в другом воспроизводят ошибку и сразу видят, что система об этом написала. Выход — Ctrl+C.

# Журнал systemd: journalctl

Службы под управлением systemd пишут в общий журнал, который читают командой `journalctl`:

```
journalctl
journalctl -f
journalctl -b
journalctl -u nginx
```

- без ключей — весь журнал от самых старых записей. Листается как в `less`: `G` — в конец, `q` — выход;
- `-f` — показывать новые записи по мере появления, как `tail -f`;
- `-b` — только записи с момента последней загрузки системы;
- `-u имя` — только записи одной службы.

Ключи можно сочетать: `journalctl -u nginx -b` покажет записи nginx с последней загрузки.

Обычный пользователь видит только собственные записи. Весь журнал доступен через `sudo` или участникам группы `adm`.

# Кто входил в систему

```
last
```

Команда показывает историю входов: имя пользователя, откуда он подключался, когда вошёл и когда вышел. Сверху — самые свежие. Строки со словом `reboot` отмечают перезагрузки.

Неудачные попытки входа показывает `sudo lastb`. Длинный список неизвестных имён с чужих адресов — обычная картина для сервера с SSH, открытым в интернет: это работают автоматические программы подбора.

# Ротация журналов

Журнал активной службы растёт без остановки. Чтобы он не заполнил диск, работает программа **logrotate**. Раз в сутки она переименовывает текущие файлы, сжимает старые и удаляет самые давние.

Результат её работы виден в каталоге:

```
syslog  syslog.1  syslog.2.gz  syslog.3.gz
```

- `syslog` — текущий журнал, в него идёт запись;
- `syslog.1` — предыдущий период;
- `syslog.2.gz` и дальше — ещё более старые, сжатые программой gzip.

Чем больше номер, тем старше файл. Если нужной записи нет в текущем журнале, она может быть в одном из предыдущих.

# Читать сжатые журналы

Распаковывать архив ради одного просмотра не нужно. У привычных команд есть двойники, которые работают со сжатыми файлами напрямую:

```
zcat /var/log/syslog.2.gz
zless /var/log/syslog.2.gz
zgrep "error" /var/log/syslog.2.gz
```

`zcat` выводит содержимое, `zless` позволяет листать, `zgrep` ищет. Сам файл остаётся сжатым.

# Коротко

- Текстовые журналы лежат в `/var/log`; входы и `sudo` — в `auth.log`.
- `tail -f файл` показывает новые записи по мере появления.
- `journalctl` читает журнал systemd: `-f` — следить, `-b` — с последней загрузки, `-u имя` — одна служба.
- `last` — история входов в систему.
- logrotate архивирует и удаляет старые журналы; файлы с номерами — прошлые периоды.
- Сжатые журналы читают через `zcat`, `zless` и `zgrep`.
