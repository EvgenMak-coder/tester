# Формат курса для Tester

Tester — приложение для тестов по IT-курсам. Вопросы оно берёт из JSON-файла: один файл — один курс. Этот документ описывает формат целиком; его можно отдать ИИ вместе с материалом курса и попросить составить файл.

## Пример

```json
{
  "format": "tester-course",
  "version": 1,
  "course": {
    "id": "linux",
    "title": "Linux",
    "description": "Базовый курс администрирования"
  },
  "topics": [
    {
      "id": "permissions",
      "title": "Права доступа",
      "questions": [
        {
          "id": "perm-001",
          "type": "single",
          "level": "basic",
          "text": "Какие права получит файл после команды?",
          "code": "chmod 640 report.txt",
          "options": ["rw-r-----", "rwxr-----", "rw-rw----", "rw-r--r--", "r--r-----"],
          "answer": 0,
          "explanation": "6 = rw- для владельца, 4 = r-- для группы, 0 = --- для остальных."
        }
      ]
    }
  ]
}
```

## Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `format` | да | Всегда `"tester-course"`. |
| `version` | да | Всегда `1`. |
| `course.id` | да | Идентификатор курса. Латинские буквы, цифры, `-`, `_`. |
| `course.title` | да | Название курса. |
| `course.description` | нет | Одна строка о курсе. |
| `topics` | да | Список тем, минимум одна. В приложении тема называется модулем. |
| `topics[].id` | да | Идентификатор темы, уникален в курсе. |
| `topics[].title` | да | Название темы. |
| `topics[].description` | нет | Одна строка о содержании темы; показывается под названием модуля. |
| `topics[].icon` | нет | Значок модуля: `terminal`, `files`, `key`, `text`, `activity`, `users`, `package`, `disk`, `network`, `lock`, `service`, `power`, `logs`, `code`, `schedule`, `shield`, `gauge`, `container`, `server`, `layers`. Без поля или с неизвестным именем показывается папка. |
| `topics[].theory` | нет | Теория модуля по уровням, см. раздел «Теория». |
| `topics[].questions` | да | Список вопросов, минимум один. |

Поля вопроса:

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Идентификатор вопроса, уникален во всём курсе. |
| `type` | да | Тип вопроса. Сейчас поддерживается только `"single"` — один верный ответ. |
| `level` | нет | Уровень сложности: `"basic"`, `"intermediate"` или `"advanced"`. Без поля вопрос считается базовым. |
| `text` | да | Текст вопроса. |
| `code` | нет | Команда, вывод или фрагмент конфига. Показывается моноширинным блоком под текстом. Переносы строк — `\n`. |
| `options` | да | Варианты ответа: от 2 до 8 строк без повторов. Обычно 5. |
| `answer` | да | Номер верного варианта в `options`, счёт с нуля. |
| `explanation` | нет | Пояснение, которое показывается после ответа: почему верен верный вариант. |
| `notes` | нет | Разбор вариантов: список строк той же длины, что `options`, в том же порядке. Каждая строка показывается после ответа под своим вариантом и объясняет, почему он не подходит. Для верного варианта обычно пустая строка: его объясняет `explanation`. |
| `shuffle` | нет | `false` — показывать варианты в порядке файла. По умолчанию варианты перемешиваются. |

## Уровни

Курс открывается набором модулей-папок. Внутри модуля вопросы делятся по вкладкам уровней, и любой режим можно запустить на одном уровне или на всех сразу. Уровень задаётся у каждого вопроса, поэтому в одной теме могут лежать вопросы всех трёх уровней.

| `level` | В приложении | Что проверяет |
|---|---|---|
| `basic` | Базовый | Повседневная работа пользователя: что делает команда, какой ключ нужен, где лежит файл, что означает термин. |
| `intermediate` | Средний | Понимание устройства и типовые задачи администрирования: настройка, чтение вывода, выбор между похожими инструментами, поиск причины простой неполадки. |
| `advanced` | Продвинутый | Нетривиальная диагностика, пограничные случаи, внутреннее устройство, безопасность и производительность. |

Вопросы разных уровней одной темы живут в одной теме, а не в отдельных: тема «Сеть» одна, уровень отличает вопросы внутри неё.

## Теория

У темы может быть теория — отдельный раздел на каждый уровень. Она показывается на странице модуля над тестами.

```json
"theory": {
  "basic": {
    "plan": ["Владелец, группа и остальные", "Права r, w, x для файла", "chmod и chown"],
    "text": "# Кому принадлежит файл\n\nУ каждого файла есть владелец и группа…"
  },
  "intermediate": { "plan": ["umask и права новых файлов", "SUID, SGID и sticky bit"] }
}
```

| Поле | Описание |
|---|---|
| `plan` | О чём раздел, по пункту на строку. Пока текста нет, модуль показывает план с пометкой «готовится». |
| `text` | Сам текст раздела. Когда он есть, в модуле появляется кнопка «Читать». |

Оба поля необязательны, уровень без плана и без текста можно не указывать.

Текст пишется в Markdown, поддерживается небольшое подмножество: заголовки `#`, `##`, `###`, абзацы, списки через `-` и `1.`, блоки кода в тройных обратных кавычках, выделение `**так**`, код в строке в одиночных обратных кавычках и врезки через `>` в начале строки. Таблиц, ссылок и картинок нет.

## Правила

1. **Идентификаторы не меняются.** Прогресс привязан к `course.id` и `id` вопроса. При повторном импорте файла с тем же `course.id` курс заменяется, а прогресс сохраняется у вопросов с прежними `id`. Исправляя вопрос, оставляй его `id`; добавляя новый — давай новый `id`; номера удалённых вопросов заново не используй.
2. **Схема идентификаторов вопросов:** короткий префикс темы и номер из трёх цифр — `perm-001`, `perm-002`, `proc-001`.
3. **Перемешивание делает приложение.** Вопросы и варианты перемешиваются при каждом запуске теста, поэтому в файле порядок может быть любым. Не пиши варианты вида «оба варианта выше» или «ответы А и В» — после перемешивания они теряют смысл. Если порядок важен (числа по возрастанию, «всё перечисленное» последним), ставь `"shuffle": false`.
4. **Верный ответ ровно один** и он бесспорен. Позицию верного варианта в `options` чередуй от вопроса к вопросу.
5. **Неверные варианты правдоподобны:** типичные ошибки, похожие команды и ключи, а не очевидная нелепица. Варианты одного вопроса близки по длине и стилю — верный не должен выделяться подробностью.
6. **Пояснение объясняет, почему** ответ верен. Одно-три предложения.
7. **Разбор объясняет каждый неверный вариант** одной-двумя фразами: что это на самом деле или в каком случае было бы верно. Не «неверно, потому что неверно», а знание, которое пригодится: «Так было бы без ключа -p», «Это порт SMTP», «Такой команды нет, список выводит jobs».
8. **Команды и вывод — в `code`**, а не в тексте вопроса. Короткие команды в вариантах ответа пишутся как есть.
9. **Один вопрос — одно знание.** Вопрос понятен без соседних вопросов и не ссылается на них.

## Как попросить ИИ составить курс

Приложи этот документ и материал (конспект, программу курса или просто название темы) и напиши, например:

> Составь по этому формату файл курса «Linux», тема «Сеть», 25 вопросов типа single с 5 вариантами, уровень basic. Выдай только JSON.

Файл курса всегда содержит курс целиком: при импорте он заменяет прежнюю версию. Чтобы дополнить курс, приложи текущий файл и попроси добавить тему, вопросы или следующий уровень, сохранив все существующие `id`.

Готовый файл импортируется в приложении на странице «Импорт»: его можно выбрать, перетащить или вставить текстом. При ошибке приложение назовёт поле, например `topics[1].questions[4].answer: индекс 5 вне диапазона`.
